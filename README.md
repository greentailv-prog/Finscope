# FinScope 统一数据接口 · 使用说明

D 模块交付给 A / B / C / E 的接口包。

五个人的模块要拼成一条链，前提是大家用同一套数据格式。这套格式由 D 定义，就是本目录的三个文件。

---

## 一、怎么用这三个文件

把本目录的**三个文件一起**发给你的 AI（Claude、ChatGPT、Copilot 都行），它就能读懂格式，帮你产出符合要求的结果：

| 文件 | 作用 |
| --- | --- |
| `README.md` | 本文件，讲全局和规矩 |
| `SCHEMA.md` | 逐字段说明，每个字段什么意思、谁填、填什么值 |
| `Schema.json` | 一份填好的完整示例，照着写 |

**开场白可以直接抄这段：**

> 我在做一个小组作业 FinScope，负责 ______ 部分。附件三个文件是我们组统一的数据接口定义。
> 请先完整读完这三个文件，然后向我复述一遍：我这个部分要产出什么数据、写成什么格式。
> 复述完，再问我几个必要的问题，然后帮我搭出我这个模块的输出骨架。
> 严格只用 Schema.json 里已有的字段名，不要自己发明新字段。

**务必提醒你的 AI**：示例公司「恒锐精密制造」和里面的所有数字都是虚构的，只用来对齐格式，不能当真实数据用。真实数据由 A 从年报里抽。

## 二、五个人的分工

| 人 | 负责什么 | 交什么 |
| --- | --- | --- |
| A | 读年报 PDF，把数字抽出来 | 带口径和页码的财务数据 |
| B | 算指标，识别风险 | 指标结果与风险清单 |
| C | 估值，Comps 与 DCF | 估值结果 |
| **D** | **定义本目录这套接口，写编排把 A/B/C 串起来，全流程测试，生成简易投研报告** | `03_Agent/` 下的编排代码与接口定义 |
| E | 前端页面，只读最终结果 | 网页 |

A、B、C 交东西时不能只交一个 SKILL.md，还要带上接口定义（INPUT / OUTPUT 说明）和最小可运行的 demo，D 才能接得上。

## 三、谁填哪一块

一份分析结果分成六个格子，各人只填自己的，E 只读不写。

| 格子 | 内容 | 谁填 |
| --- | --- | --- |
| `company` | 公司名称、代码、行业、报告期、币种 | D 定字段，A 补值 |
| `financials` | 25 个财务科目，带单位、口径、页码 | A |
| `ratios` | 五类共 25 个指标，每个带公式 | B |
| `risks` | 风险卡片，带触发条件与证据 | B |
| `valuation` | comps 与 dcf 两块估值 | C |
| `sources` | 数据来源清单 | A 归集 |

## 四、七条硬规矩

这七条最容易写错，发文件给你的 AI 时最好一并强调。

1. **金额一律用百万元。** 186.5 亿元要写成 `18650`，不是 186.5 也不是 18650000000。美股公司币种填 USD，读作百万美元。
2. **比率是纯数字，不带百分号，保留一位小数。** 28.5% 写成 `28.5`。
3. **精度按数据本身来，最多两位小数，不要补零。** 有几位写几位。
4. **每条财务记录必须带 `scope` 和 `basis`。** 写明是合并报表还是母公司报表，是累计数、单季数还是期末数。缺了这两项，这条记录算无效。
5. **每条财务记录必须带 `page`。** 标出数字在年报的第几页。项目的核心承诺就是每个数字都能点回原文。
6. **归母净利润固定写 `net_income_parent`。** 不要写成 net_income、net_profit 或其他名字。
7. **不知道的写 `null`，确定是零写 `0`。** 两者不能混。没有这个数据，和这个数据确实是零，是两回事。

## 五、数据怎么往下传

```
用户上传年报 PDF
  → Financial Extraction    → financial_data.json     (A)
  → Financial Diagnosis     → financial_analysis.json (B)
  → Risk Radar              → risk_analysis.json      (B)
  → Valuation (Comps + DCF) → valuation.json          (C)
  → Report Generation       → final_report.json       (D)
  → 前端展示                                          (E)
```

每一步的产物都回填进**同一个**对象，只往六个格子里加内容，不换字段名。下游读的永远是同一个结构。

## 七、已知的两个不一致（还没修，先留意）

1. `ratios` 里有 6 条公式写了 `accounts_receivable_begin`、`inventory_end` 这类名字，但 `financials` 里没有这些键。实际约定是：`value` 是本期，`prior_value` 是上期。看公式时按这个理解。
2. `valuation.comps.inputs` 里的归母净利润用了 `net_income`，按规矩应该叫 `net_income_parent`。两处指同一样东西。

## 八、验收标准

A、B、C 的产物串成一条链跑通：上传年报 → A → B → Risk → C → Report，输出统一的报告 JSON。

E 不打开任何 Skill 文件，只读最终输出的 JSON 就能把六个页面全部渲染出来。
