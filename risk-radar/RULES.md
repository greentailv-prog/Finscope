# RULES.md — risk-radar 风险分级与判断标准

> 分工文档要求 A/B/C 各交一份 `RULES.md`，写"金融规则与判断标准"。
> 本文件是 B 的**风险判断规则**：怎么分级、怎么取证、怎么控制误报。
> 规则本体（40 条触发条件）见 `risk_rules.json`。

---

## 一、风险分级标准

### 1.1 三档严重度

| severity | tag | 判断标准 | 处理动作 |
|---|---|---|---|
| `high` | **重大** | 已构成实质性财务风险，或**报表可信度存疑** | 投研简报单列提示；必须回到年报附注追查原文 |
| `medium` | **关注** | 存在明确恶化趋势或结构性隐患 | 在归因章节解释成因；列入持续跟踪项 |
| `low` | **提示** | 偏离常态但未构成风险 | 列为观察项 |

> 分工文档示例里写的 `severity: "attention"` 统一映射为 `medium`（关注档）。

### 1.2 什么算"重大"：三条红线

满足任一条即直接定 `high`，不看阈值：

1. **报表可信度存疑** —— 非标审计意见（A03）、存贷双高（A02）
2. **现金流断裂风险** —— 经营现金流为负（C02）、现金覆盖不住短期有息债务（S03 升级档）
3. **核心质量指标失守** —— 净现比长期低于 0.8（C01 升级档）、自由现金流/收入低于 −5%（C03 升级档）

### 1.3 基础档 + 升级档机制

每条规则有 `severity`（基础档）和可选的 `escalate_when` / `escalate_to`（升级档）：

```jsonc
"severity": "medium",
"escalate_to": "high",
"escalate_when": "cash_to_short_term_debt < 1.0"
```

好处是同一条规则可以表达"偏薄"与"危险"两种程度，而不用拆成两条。

### 1.4 确定性分级：严重度表达对应会计判断的确定性

风险严重度本质上是"这条结论有多确定"。参考会计准则实务中的确定性分级
（**应当** → **建议可以** → **可能** → **原则上**），本模块把三档严重度映射为对应的表达强度。
前端与投研简报应照此措辞，避免把"可能"说成"一定"：

| severity | tag | 表达强度 | 措辞范式 |
|---|---|---|---|
| `high` | 重大 | 应当（强确定） | "已构成实质性风险，**应当**……" |
| `medium` | 关注 | 建议可以（中确定） | "存在恶化趋势，**建议关注**……" |
| `low` | 提示 | 可能（弱确定） | "可能偏离常态，**留意**……" |

> 注意：`passed`（未触发）≠ 确定安全。它仅表示"本条已查、未达触发线"，不是"该项无风险"。

## 二、证据链规范

### 2.1 六层结构（不可省略任何一层）

| 层 | 必须包含 | 缺了会怎样 |
|---|---|---|
| **数据** | 触发用到的每个原始字段的本期值、上期值、年报页码 | 无法核对，沦为"黑箱结论" |
| **计算** | 触发表达式原文 + 各变量的实际值 | 无法复算，无法证伪 |
| **出处** | 涉及的年报清单 + 页码汇总 | E 的"跳到原文"功能失效 |
| **判断** | 中文触发条件 + 判定结果 + 严重度 | 读者看不懂为什么触发 |
| **归因** | 杜邦三段、营业利润桥、现金流桥 | 只说"有风险"，不说"为什么" |
| **建议** | 3–4 条具体可执行的下一步 | 无法指导后续研究 |

### 2.2 证据的三条质量标准

| 标准 | 内容 |
|---|---|
| E1 | **可追溯**：每个数字都能定位到年报的具体页码 |
| E2 | **可复算**：给出公式与输入值，任何人都能算一遍得到同样结果 |
| E3 | **可证伪**：明确写出"什么情况下这条风险不成立"，而不是只说它成立 |

## 三、误报控制（最重要的一节）

财务风险规则的**误报成本远高于漏报**——一条错误的"存贷双高"指控可能直接毁掉一份研报的可信度。

### 3.1 三条误报控制纪律

| 编号 | 纪律 |
|---|---|
| F1 | **规则是线索，不是结论。** 触发后必须回到年报附注与原始凭证核实，禁止仅凭指标下结论。 |
| F2 | **存疑规则必须人工确认。** `confidence` 低于 0.8 的规则（A02 存贷双高 0.75、A04 研发资本化 0.70、P06 行业对比 0.60），触发后**一律进 `review_queue` 并标记 `needs_human_judgement: true`**，不得直接写进投研简报的"风险提示"章节。 |
| F3 | **缺失输入不得判安全。** 一律 `not_evaluable` + 转人工。 |

### 3.2 已知的高误报风险规则与缓释方式

| 规则 | 误报来源 | 缓释 |
|---|---|---|
| **A02 存贷双高** | 集团财务公司、境外资金、保证金账户都可能造成"账上有钱还借钱" | 三条件同时成立才触发；必须核对利息收入率、受限资金、其他应收款 |
| **E03 DSO 绝对水平** | 工程设备、军工、政府客户的账期天然更长 | 行业阈值放宽到 180 天以上；看变化速度优先于绝对水平 |
| **S01 资产负债率** | 银行地产 80% 属常态，零售业有大量无息预收 | 剔除预收款后的"真实杠杆"；按行业重设阈值 |
| **C05 收现比** | 含税口径、票据结算都会影响 | 跨公司比较必须统一口径；票据占比需单独看 |
| **S04 利息保障倍数** | 资本化利息会虚增保障倍数 | 用"经营现金流/已付利息"（C06）交叉验证 |
| **P06 行业对比** | 可比口径不一致 | 行业基准缺失时直接 `not_evaluable`，不拍脑袋 |

### 3.3 行业校准优先于通用阈值

`risk_rules.json` 里的 60% / 120 天 / 1.0 倍是**制造业通用档**。
正式使用必须按行业重设，校准表见 `data/industry_calibration.json`。

### 3.4 行业剖面机制（v1.1 已实现）

上面那条"必须按行业重设"原本只是规范，**现在已经落地成可执行机制**。

剖面文件在 `data/industry_profiles/`：

```
_index.json        剖面索引：关键词 → profile_id，用于自动匹配
banking.json       银行业
manufacturing.json 制造业（通用档基线）
```

一个剖面提供四层能力：

| 层 | 字段 | 作用 |
|---|---|---|
| ① 指标适用性屏蔽 | `metrics_not_applicable` | 该行业不成立的指标直接不算、不进待核验队列 |
| ② 阈值覆盖 | `threshold_overrides` | 同一条规则换行业用不同阈值，**改数据不改代码** |
| ③ 行业专属规则 | `extra_rules` | 追加该行业特有的风险规则 |
| ④ 监管底线 | `regulatory_basis` | 把"低于监管红线"和"低于同业均值"区分开 |

**为什么第 ④ 层重要**：越监管红线是合规问题，低于同业是竞争问题。
这两件事的风险含义完全不同，混在一起谈会让风险等级失去意义。

#### 银行业剖面的实际效果（工商银行实证）

| | 银行业剖面 | 制造业通用口径（误用） |
|---|---|---|
| 规则总数 | 53（40 通用 + 13 专属） | 40 |
| 正确屏蔽为「不适用」 | **30** | 0 |
| 触发 | 3（重大 0） | 2（**重大 1**） |
| 不可评估 | 2 | 23 |
| 待核验项 | **2** | **66** |

误用口径下，S01「资产负债率偏高」被判为**重大**——但银行资产负债率常态就在 90% 以上，
这是彻头彻尾的误报。行业剖面把这类噪声整类屏蔽掉，
**不是少报风险，是不报假风险**。

#### 当前的诚实边界

银行业剖面的阈值取自**公开监管规则与公开行业统计均值**，
**尚未用可比公司分位数做统计校准**。这一点在输出的 `industry_profile` 段里
用 `benchmarks_calibrated: false` 明确标注。

要完成真正的行业校准，只需 C 提供可比公司池的 P25 / P50 / P75 分位数，
填进 `meta` 的 `industry_*_benchmark` 字段后重算，**无需改任何代码**。

## 四、规则的分类与覆盖

40 条规则分七类，覆盖分工文档要求的五个维度（成长性 / 盈利能力 / 偿债能力 / 营运能力 / 现金流质量），
另加两类扩展（资产质量 / 治理分红）：

| 类别 | 规则数 | ID 段 | 覆盖要点 |
|---|---|---|---|
| 成长性 | 5 | G01–G05 | 收入下滑、利润下滑、增收不增利、扣非占比、现金流背离 |
| 盈利能力 | 7 | P01–P07 | 毛利率、ROE、ROE vs WACC、ROIC vs WACC、费用率、行业对比、财务费用率 |
| 偿债能力 | 8 | S01–S08 | 杠杆水平与速度、期限错配、利息覆盖、净负债/EBITDA、受限资金 |
| 营运能力 | 7 | E01–E07 | 应收跑赢收入、DSO 延长与绝对水平、存货积压、CCC、周转率、营运资金占比 |
| 现金流质量 | 7 | C01–C07 | 净现比、OCF 为负、FCF、资本开支缺口、收现比、利息覆盖、融资依赖 |
| 资产质量（扩展） | 4 | A01–A04 | 商誉、存贷双高、非标审计意见、研发资本化 |
| 治理分红（扩展） | 2 | V01–V02 | 分红率、分红超过经营现金流 |

**扩展类的说明**：资产质量与治理分红不在分工文档列的五维度里，
但它们需要 A 提供额外字段（商誉、审计意见、研发资本化、分红），
且是财务造假研究里命中率最高的红旗。**建议保留**，若 A 无法提供对应字段，
这些规则会自动返回 `not_evaluable`，不会影响主流程。

## 五、与其他模块的边界

| 边界 | 规则 |
|---|---|
| 与 `financial-diagnosis` | Risk Radar **不重新计算任何指标**。所有数字来自 `ratios`，保证口径一致。 |
| 与 C（`valuation`） | 风险结论要传导给估值：如 ROIC < WACC → 建议下修成长性假设；流动性紧张 → 建议加入再融资失败情景。这些写在规则的 `suggestions` 里，用「向 C 明确：」开头。 |
| 与 D | D 只做搬运，不改风险等级。 |
| 与 E | E 只读渲染，不重新判断。 |

## 六、规则库维护规范

改 `risk_rules.json` 时遵守：

1. **不动 `risk_id`。** E 前端可能有硬编码映射，改 ID 会静默失效。
2. **新增规则必须写全六个字段**：`trigger` / `trigger_display` / `evidence_required` /
   `explanation_template` / `suggestions` / `confidence`。缺任何一个，证据链就断一层。
3. **`explanation_template` 只能引用已存在的变量。** 引用不存在的变量会让整句降级成"需人工补全"，
   演示时很尴尬。新增变量请在 `derived_vars` 里定义。
4. **阈值要写进 `trigger_display`。** 让非技术读者一眼看懂触发标准是什么。
5. **`confidence` 要诚实。** 有行业依赖或需要外部数据的规则，一律压到 0.8 以下。

## 八、会计判断的权威依据（风险判定为什么这么定）

本模块的"不默认安全""监管导向""确定性分级"并非个人偏好，而是会计准则实务框架的
直接应用，可追溯、可复核。完整引用见 `../references/accounting_standards_basis.md`。

### 8.1 谨慎性底线 → 缺失不得判安全（F3）

《企业会计准则——基本准则》第十八条（谨慎性）：不确定性下不确认收益、损失从快确认。

→ 对应 F3：输入缺失一律 `not_evaluable` + 转人工，**绝不默认"通过"**。
"算不出来 ≠ 没问题"是投研场景最危险的认知错误——把缺失当成安全，等于替公司背书。

### 8.2 监管导向 → 阈值要分"越红线"与"低于同业"（行业剖面④）

《监管规则适用指引——会计类》（证监会）、《商业银行资本管理办法》
（资本充足率监管底线）、《商业银行贷款损失准备管理办法》（拨备覆盖率监管底线 120% / 150%）、
《商业银行流动性风险管理办法》（流动性覆盖率 LCR ≥ 100%）等，构成银行类指标的"监管红线"。

→ **越红线是合规问题，低于同业均值是竞争问题，风险含义完全不同。** 行业剖面第④层
`regulatory_basis` 把二者分开；阈值设计应优先引用监管红线，其次才是对标同业分位数。
（当前银行业剖面阈值取自公开监管规则与公开行业统计均值，尚未做可比公司分位数统计校准，
已在输出中以 `benchmarks_calibrated: false` 诚实标注。）

### 8.3 规则是线索不是结论（F1）→ 实质重于形式

触发一条规则只说明"指标异常"，不等于"坐实风险"。尤其 A02 存贷双高、A04 研发资本化，
必须回到年报附注与资金流水，按**实质重于形式**核实交易背景（集团财务公司、受限资金、
境外资金都可能造成"账上有钱还借钱"的假象），禁止仅凭指标下结论。
误报的代价（一条错误的"存贷双高"指控）远高于漏报。
