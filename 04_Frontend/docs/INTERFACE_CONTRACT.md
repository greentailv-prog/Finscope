### 6. `sources[]` 需要「怎么打开原文」的字段（新增，2026-10-10）

**背景**：全站定了一条原则 —— 数据来源要标出来，但不和数据抢注意力：
以低调的可点击文字贴在它支撑的那个数字旁边/下面，**点击后回到原数据位置**。

E 现在把「回到原数据位置」实现成了一个浮层，点页码弹出：

```
指标    应收账款
数值    38.7 亿元
期间    2025
来源文件 2025年年度报告
章节    第十节 财务报告
页码    P.80
```

**问题是这只到「告诉你在哪」，没到「带你过去」**。用户看完还是得自己
翻年报找第 80 页。因为 `sources[]` 里只有文档名，没有可跳转的地址：

```json
{ "source_id": "S3", "metric": "应收账款",
  "source": "2025年年度报告",           // ← 只有名字，没有地址
  "section": "第十节 财务报告", "page": 80 }
```

**请 D 在 `sources[]` 每个条目上加一个可跳转地址字段**，二选一：

| 字段 | 形式 | 适用 | 评价 |
|---|---|---|---|
| `url` | `"https://.../report.pdf#page=80"` | 年报有公开下载链接（巨潮/官网） | ✅ 最理想，双击 HTML 就能开 |
| `file` | `"../05_Output/2025年年度报告.pdf#page=80"`（**相对路径**） | PDF 随交付包一起打包 | ✅ 也可，但要求 PDF 一起交 |

```json
{ "source_id": "S3", "metric": "应收账款",
  "source": "2025年年度报告",
  "section": "第十节 财务报告", "page": 80,
  "url": "https://www.cninfo.com.cn/....pdf#page=80" }   // ← 新增
```

**若同一家公司只有一个年报文件**，也可以只在 `company` 下给一次：

```json
"company": { "report_title": "2025年年度报告",
             "report_url": "https://....pdf" }
```

E 侧取用顺序：`sources[].url` → `company.report_url` → 都没有就维持现状（纯浮层）。

**两个必须提前说清的坑**：

1. **`file://` 下只有相对路径能用**。绝对路径（`D:\...`）只在你自己机器上有效，
   换台电脑演示就断。要打包 PDF 的话，位置和相对路径请和 E 约定好。
2. **`#page=80` 这种锚点只有 Chrome 系内置 PDF 阅读器认**。若演示环境是别的浏览器，
   退化成「打开 PDF 的第 1 页」，但不影响可用性。

**非阻塞**：没有这两个字段，页面 4 / 2 / 3 的溯源浮层照常工作，只是不能真跳转。
有的话 E 会在浮层底部加一个「打开原文 ↗」链接，零改动接入。

### 7. `valuation` 下的金额字段没有 unit（**新增，2026-10-13，找 D / C**）

这一条是接真数据时发现的。**同一个 Schema 里两套单位词汇，而且有一半的金额
根本没有单位声明。**

没有 unit 的（一个都没有）：

```
valuation.comps.inputs.*              （营收、净利润、股本…）
valuation.dcf.inputs.revenue_base
valuation.dcf.forecast[].*            （三情景各自的一串预测）
valuation.dcf.terminal_assumptions.*  （tv_gordon / tv_exit / tv_divergence…）
valuation.blended.*                   （融合后的股权价值 / 每股价值）
valuation.scenarios.*.equity_value
```

对照之下，Schema 对 `company.amount_unit` 与 `financials.*.unit` **都写明了「元」**。
`valuation` 里唯一带单位的是：

```json
"valuation_range": { "low": …, "mid": …, "high": …, "currency": "元/股" }
```

⚠️ **`currency` 管的是「每股价格」，管不到上面那些总额** ——
这是最容易误读的一处。

**E 现在怎么办**：按 D 自己在 memo 里的写法推定是「元」，再换算成亿元显示。
**这是刻度换算，不是重算**（E 不重新推导任何指标值）。但「推定」这件事
在现场解释不清 —— 演示时被追问「你怎么知道是元」，答案不能是「猜的」。

**请 D/C 二选一**：
① 给这些字段补 `unit`；或
② 在 `Schema.json` 里明确写一句「`valuation` 下的金额一律为元」，
   让它成为契约而不是共识。

**顺带**：`valuation_range.currency` 与 `financials.*.unit` 是**同一个概念两个名字**。
E 侧两条都接了（`currency` 优先、退化到 `unit`），但接口应该只有一种写法 ——
两个名字并存的结果是下一个人要读两遍代码才知道它们是一回事。

**E 的处置**：一个数都不改。只按三条判据（量级突变 / 量级不对 / 自相矛盾）

**改数会让错误消失** —— 页面看着干净了，而 A 永远不知道抽取器坏了。
详见 `docs/EDGE_CASES.md` #105 与 #102–#104。

**另有一条结构事实需要 D / A 对齐**：
D 目前只交付 **1 家**（600519.SH 贵州茅台），`window.FINSCOPE_DATA`
顶层是 `company / financials / ratios / risks / rules_evaluated / valuation / sources`，
**不是按公司 code 索引的**；而 A 交付 **9 家**。

说明两边自洽，是好消息；但也意味着**页面 1 的看板是目前唯一能看到另外 8 家的地方**。

### 2. `financials.capex` 的符号口径（新增，2026-10-10）

页面 2 的主要财务数据表把「现金流量表」这一块画成**零点线分左右**，
因为 `cfo` / `cfi` / `cff` 三项都是**净额**，正负号表示资金流向。

**资本开支（`capex`）不是净额，是流出发生额**，所以 E 把它从左右分流里
单独拎出来，用普通幅度条渲染（`dataLoader.js` 的 `FINANCIAL_BOOK` 里
逐行覆写了形状）。

**请 A 明确一件事：`capex` 传正数还是负数？**

| A 传的实际值 | E 现在的渲染 | 问题 |
|---|---|---|
| `+16.9` | 数值「16.9 亿元」，条向右画 | 无（E 现在按这个假设做的） |
| `−16.9` | 数值「−16.9 亿元」，条**仍向右**画（取绝对值） | ⚠️ 数字的符号与条的方向打架 |

E **不会**替 A 翻符号 —— 翻符号等于替 A 重算口径，那是越界。
所以在 A 明确之前，页面上按取绝对值处理。

请回答：**① 传正还是传负？② 要不要在页面上标方向词「资本开支（流出）」？**

### 3. `company.business` —— 一句话业务定位（新增，2026-10-10）

加在 `company` 里，与 `industry` / `report_period` 并列：

```js
company: {
  /* 原有的 5 个字段不动 */
  business: "以输配电设备为主业，同时经营新能源设备与智能电网系统，"
          + "客户以电网公司及大型工业用户为主。",
  business_page: 12          // 上面那句话出自年报第几页
}
```

| 约定 | 说明 |
|---|---|
| 长度 | **一到两句话，40–80 字**。不要贴整段「公司业务概要」——那一节动辄上千字，放进抬头就没人读了 |
| 口吻 | 陈述事实，**不要形容词**（「行业领先」「技术优势明显」这类是投资叙事，不是业务定位） |
| 出处 | `business_page` 填年报「公司业务概要 / 主营业务」那一节的页码 |
| 缺失 | 两个都不给：整行不出现，页面不留空位。**不要传 `""`** |

E 拿它做什么：放在公司抬头下面，正文样式，带一个可点开的页码。
它是页面 2 唯一一句不是数字的内容 —— 作用是让下面那堆数字有落脚点：
不写，读的人不知道 128.6 亿是从哪个业务里长出来的。

### 4. `business_mix` —— 主营构成（新增，2026-10-10）

顶层新增一个块，与 `financials` 平级：

```js
business_mix: {
  period: "2025",                       // 归属期间
  source: "2025年年度报告",
  section: "第三节 管理层讨论与分析 · 主营业务分产品情况",   // 可缺
  page: 83,                             // 整块的主页码，可缺
  items: [
    { name: "输配电设备",   revenue: 79.7, unit: "亿元", share: 0.62, page: 83 },
    { name: "新能源设备",   revenue: 33.4, unit: "亿元", share: 0.26, page: 84 },
    { name: "智能电网系统", revenue: 15.5, unit: "亿元", share: 0.12, page: 84 }
  ]
}
```

| 字段 | 必填 | 约定 |
|---|---|---|
| `name` | ✅ | 业务/产品名，**原样显示，E 不翻译、不合并** |
| `revenue` | ✅ | 金额，单位见 `unit` |
| `unit` | 可缺 | 缺省继承顶层的 `unit` |
| `share` | ✅ | **占营业收入的比重，小数**（`0.62` = 62%，与全站口径一致） |
| `page` | ✅ | 该项出自年报第几页 |

**三条要请 A 注意的：**

1. **`share` 请由 A 给，不要让前端算。** 占比会被读成结论（「公司 62% 收入靠输配电」），
   结论不能由前端推导 —— 那是 E 越界。
   E 的处理：`share` 缺就从缺，那一项只列金额、**不画条、不写百分数**。
2. **口径必须是「加总 ≈ 营业收入」**，即分产品 / 分地区 / 分行业这类**完备拆分**。
   如果是「前五大客户」这种不完备拆分，占比之和远小于 100%，
   而页面上那根条是「轨道整条 = 100% 营业收入」，会读错。**这类请另开字段，别塞进 `items`。**
3. **`share` 传小数，不是百分数**（传 `0.62` 不传 `62`）。
   E 会把 0–1 之外的值当作「未提供」并 `console.warn` ——
   既不照乘成 6200%，也不顺手除一下（那等于替 A 定口径）。

`items` 的顺序 E **原样照排，不重排**（通常是按收入降序）。排序规则是口径，不是排版。

### 5. `history` —— 多期趋势（新增，2026-10-10）

```js
history: {
  unit: "亿元",                          // 各系列的缺省单位
  source: "2025年年度报告",
  series: [
    { key: "revenue", name: "营业收入",
      values: [ { period: "2023", value: 95.0,  page: 40 },
                { period: "2024", value: 108.6, page: 60 },
                { period: "2025", value: 128.6, page: 82 } ] },
    { key: "net_income_attr", name: "归母净利润",
      values: [ { period: "2023", value: 8.9,  page: 40 },
                { period: "2024", value: 10.73, page: 60 },
                { period: "2025", value: 11.4, page: 84 } ] }
  ]
}
```

| 字段 | 必填 | 约定 |
|---|---|---|
| `values[].period` | ✅ | 期间标签，`"2023"` / `"2023H1"` / `"2023Q3"` 都行，**原样显示** |
| `values[].value` | ✅ | 金额 |
| `values[].page` | ✅ | 该期数据出自年报第几页（逐期页码是这块的价值所在） |
| `series[].unit` | 可缺 | 缺省继承顶层 `unit` |
| `series[].name` | ✅ | 中文名，直接当小标题显示 |

**三条要请 A 注意的：**

1. **`values` 必须按时间升序给。E 不排序** —— 期间是字符串，`"2023H1"` 会被排到
   `"2023"` 后面。顺序由 A 负责。
2. **只给绝对值，不要给同比增速。** 增速是 B 的 `ratios.growth` 的活，
   在图里标一个增速 = 前端替 B 出了一版数据。E 只在页面上画 `value`。
3. **少于 2 个点的系列，E 会直接不画**（一个点画不成趋势），并在控制台留痕。
   如果某个系列本来就只打算给一期，请干脆不要放进 `series`。

**为什么单开一块，而不是把 `financials` 从单期改成多期**（请 A 知悉这个取舍）：
`financials` 一改，页面 2 的 16 行明细表、B 的 `ratios` 单期口径、
C 的估值对象都要跟着动。单开 `history` 是纯加法 ——
A 的排期风险从「改口径」降到「多抽一张表」，其他人的工作一行都不用改。
