### 版式定案（2026-10-10）

1. **本页讲一句话：数字必须可验证**。演示台词就是这个（`DEMO_SCRIPT.md:42`
   「每个数字下面都标了年报页码，点开可以溯源……数字必须可验证」），
   所以版面重心不是「几个好看的数」，是**每个数旁边都有一条能点开的页码**。
2. **本页零 tone**。曾计划给三个大数配同比的涨跌色，定案时否掉了：
   卡片顶边和右上角健康度标签已经在用 status 色（红/黄/绿），再加一套红涨绿跌，
   同一张卡上红色会同时表示「上涨」和「差」。**同比归页面 3 的成长性维度讲**，
   那里已经是它的主场。`base.css` 的 tone 因此全站零使用，保留待用。
3. **加一张「主要财务数据」表**（2026-10-10 新增）。原先页面 2 下半部分靠一张
   开发期的「骨架自检」kv 卡撑着，那是脚手架，已删。取而代之的是
   16 个财报科目，按三张报表分块。
4. **16 行不能排成一张同样的表**（2026-10-10 当晚返工）。
   第一版做成了一张四列表（科目 / 数值 / 期间 / 出处），数据齐全，
   但**同字号、同颜色、同列宽，眼睛没有落点** —— 更糟的是三张报表本来
   各有各的形状，压成同一个模板之后，「刻板」就是从这儿来的。
   现在做三件事：
   - **块内保留报表自身的形状**：利润表有缩进层级与「减：」；
     资产负债表用「其中：」表示从属（货币资金 / 应收账款 / 存货 / 商誉
     是总资产下面的细项），并且**总负债与归母净资产移到细项之后** ——
     放在中间会被读成「其中」的一部分；
   - **每行配一条比例条**，大小关系不用读数字就看得出来；
   - **快慢两条车道**：每块一行头条科目（营收 / 总资产 / 经营现金流）
     字号大一档，其余退到次级。全都一样重，就是全都看不到。
5. **三块各有一个 headline 科目，写在块头上**（`.fin-block-flag`）。
   看一眼就知道这块是张什么表、体量多大，不用先读完行才知道。
6. **现金流量表用零点线分左右**，因为三项都是**净额**，正负号表示流向
   而不是大小 —— 这是三张表里形状最不一样的一张。
   **资本开支是例外**：它是流出额、不是净额，所以逐行覆写回普通幅度条
   （`FINANCIAL_BOOK` 里 `{ key: "capex", gap: true, shape: "plain" }`）。
   ⚠️ **不翻符号**：数据里资本开支是正的 16.9，E 不许把它改成 −16.9
   来迁就图形 —— 那是替 A 重算口径。形状服从数据，不是数据迁就形状。
7. **不画等号**。利润表里归母净利润上面那道分隔线，以及资产负债表里
   总负债上面那道，都只是「以下是结论行」的分隔线，
   **不是算术等号**：利润表中间隔着本表列不全的费用和税；
   资产负债表的归母净资产不含少数股东权益，真数据下
   「资产 = 负债 + 权益」并不成立，画出来就是错的。
8. **比例条是显示缩放，不是金融比率**。条长按**本块内**绝对值最大的科目
   归一（不跨块比 —— 利润表和资产负债表不是一个量纲），
   所以页面脚注里必须写明「等比缩放……不是任何比率」，
   免得被读成「这个科目占营收多少」。这一条不是免责声明，
   是**防误读**：不写，观众一定会那样读。
9. **出处一律低调**：小一号、灰色、虚线，紧贴它支撑的那个数字。
   全站原则见 `css/components.css` 的 `.page-link` 注释。
10. **缺数据写「未提取」，不写破折号**。`—` 分不清是「没有这个数」还是「这个数就是零」。
    两个大数没有数据时的来源行写「无数据可溯源」，不编一个链接出来。
11. **ROE 的来源行是「由财务数据计算得出」**，不是缺数据 ——
    它是几个科目算出来的，没有单一页码。这也是向 B 要 `page` 的原因（见下）。
12. **本页不只讲财务**（2026-10-10 追加）。第一版整页从上到下都是钱。
    现在在抬头下加一句话业务定位，在大数与明细表之间加一排两块 ——
    「钱从哪来」（主营构成）和「这几年怎么长过来的」（多期趋势）。
    叙述顺序变成：**是什么 → 有多大 → 钱从哪来 / 长了多少 → 全部明细（可溯源）**。
    这句话和这两块都不改变本页的主张（数字必须可验证），只是让数字有落脚点。
13. **新增两块排成一行两栏**（`.two-col.ctx-row`），不上下堆叠 ——
    两块各自不长，堆起来会把「主要财务数据」表推到第三屏，
    而那张表才是本页那句演示台词的载体。
    两栏**等高**（`.ctx-row { align-items: stretch }`，不改 `.two-col` 默认值 ——
    页面 5 的 Comps / DCF 两块本来就该各按自己内容高）。
    理由同页面 3：并排两块底边不齐，看着像没做完。
    缺一块就整块不渲染，由 `auto-fit` 让剩下那块占满整行，不留半空的格子；
    两块都缺就整条带子不出现，也不留一条空栅格。
14. **两种条长的含义不同，必须分别注明**：
    - 主要财务数据表的条 = **本表内相对大小**（显示缩放，与画柱状图算刻度同类）；
    - 主营构成的条 = **占营业收入的百分比**（A 给的 `share`）。
    同一个灰蓝组件、两种刻度，所以两块各自有一条脚注，说清自己是什么刻度。
    主营构成那块是**全页唯一「轨道整条本身就是 100%」**的地方。
15. **多期趋势只画绝对值，不画增速**。增速是 B 的 `ratios.growth` 的活，
    在图里标一个增速 = 前端替 B 出了一版数据（越界）。
    与定案 2（本页零 tone）一致：没有涨跌，也就没有涨跌色。
16. **多期趋势用 DOM 条形，不用 `charts.js` 的 `trend()`**。
    那个函数是为此预留的，但 canvas 上挂不了页码链接 ——
    图里的数一旦点不开，全页就出现了唯一一批不可验证的数字，
    正好把自己的招牌拆了。DOM 还顺带解决打印发虚和没法被测试断言这两件事。
    `trend()` 保留不删：等将来出现「十几期、且不需要逐点溯源」的场景，
    那时它才是对的工具。
17. **趋势的期间顺序原样照排，E 不排序**。期间可能是 `"2023H1"` 这类字符串，
    按字符串排会把中期排到年末后面。顺序由 A 保证（合同里写死「时间升序」），
    测试里专门有一条**反着给**的用例来证明前端确实没排序。
18. **本页把 13px 这一档整个拆掉**（2026-10-12，字号阶梯 B 方案）。
    起因：「一堆没有分辨度的数据让人没有仔细看的耐心」——
    用 `tools/layout-audit.js` 量出来，问题不在装饰不够，在**阶距不够**：
    12 / 13 / 14 / 16 相邻只差 1.083 / 1.077 / 1.143，低于肉眼能分辨的
    ≈1.15，四级读成一级。改法是**拆用法**而不是改数值（中文在 12–16 之间
    只有 4px 可用余量，硬拉要靠整体上移字号，代价是每处密排都要重排）。
    本页 7 处 13px 的去向：

    | 规则 | 原 | 现 | 依据 |
    |---|---|---|---|
    | `.fin-table`（三张报表体） | 13 | **14** | 要读的内容 |
    | `.company-brief-text`（业务定位句） | 13 | **14** | 本页唯一一句正文 |
    | `.mix-name` / `.mix-value` | 13 | **14** | 要读的内容 |
    | `.trend-name` / `.trend-value` | 13 | **14** | 要读的内容 |
    | `.fin-block-name`（「利润表」块名） | 13 | **16** | 见下 |

    两条值得单记：
    - **`.fin-block-name` 必须大于它自己那张表的表体**。原先块名 13 = 表体 13，
      标题不高于正文，是反的。块名是「这三块表分别是什么」的唯一分节信号，
      扫不到它，三块就糊成一块。定 **16**，与 `.fin-row.is-headline .fin-value`
      （头条科目值）同号 —— 两者本就是同级：一个说「这块表叫什么」，
      一个说「这块表最重要的数」。位置（灰底条 vs 表行）与底色已把角色分开。
    - **`.mix-share`（主营占比）一并从 14 抬到 16**。它本不是 13px，是 B 的
      **连带**：原先它靠「14 比旁边的 name/value 的 13 高一格」撑住「结论数字」
      的身份，13 档取消后这 1px 的优势就没了。抬到 16/700 后，
      「块级结论数字」全页统一 —— 头条科目值 16/700、主营占比 16/700。

    改完本页字号层级为 **12 / 14 / 16 / 20 / 26 / 34**，
    相邻比 1.167 / 1.143 / 1.250 / 1.300 / 1.308，**全部 ≥ 1.14**。
    当时 `--fs-sm` 这一行**留在** `base.css`（另有 19 处在用），
    等六页 + 共享段全部挪完再由最后一次变更删掉 —— 这样逐页改不会中途把站弄坏。
    **已于 2026-10-12 全部挪完并删除**，收尾见本文末「共享段 · 字号阶梯 B 方案收尾定案」。
    与「每个数字都要能点开溯源」是同一个原则：**层级要能被读出来，才谈得上可核对**。

**降级行为**：`financials` 整块缺失时，主要财务数据表显示空状态而不是空白表格；
单个科目缺 `page` 时，出处列显示灰破折号，**不编链接**；
单个科目 `value` 为 `null` 时，数值列显示 `—`，并且**该行不画比例条**
（留一根空轨道比不画更容易被误读成一个很小的数）。
词汇表（`dataLoader.js` 的 `FINANCIAL_BOOK`）里没登记、但数据里出现的科目
会兜进「其他」组 —— 宁可多显示一行，也不静默藏起来；
词汇表里登记了、数据里没有的科目整行不出现，其余行照常，分块不塌。

| 缺什么 | 页面表现 |
|---|---|
| `company.business` 缺 | **整行不出现**，不留一个写「未提供」的空行（缺一句叙述不值得占一格；与缺数字不同 —— 缺数字是研究结论的缺口，要看得到） |
| `company.business_page` 缺 | 句子照显示，**不编一个页码出来** |
| `business_mix` 缺 / `items` 空 | 主营构成整块不渲染；多期趋势自动占满整行 |
| 某项 `share` 缺 | 该项**不画条**（不画空轨道 —— 会被读成「占比 0%」），占比列写 `—`，脚注点明「N 项 A 未提供占比」 |
| `share` 传成 `62`（已乘过 100） | 按「没提供」处理。**不照乘成 6200%，也不顺手除一下** —— 前者是错的读法，后者是替 A 定口径。同时 `console.warn` |
| `share` 恰为 `0` | **保留 `0`**（`0` 是有效值，不是缺失，见 `EDGE_CASES` 10） |
| `history` 缺 | 多期趋势整块不渲染 |
| `history` 在但每个系列都不足 2 个点 | 出一张卡说明「画不成趋势（趋势至少要两个点）」—— 不说的话 A 会以为前端没接上 |
| 单个系列不足 2 个点 | **只剔掉那一系列**，其余照画（一个点画不成趋势） |
| `history` 结构不合法（传成数组） | 当这个字段不存在：整块不出现，也**不顺嘴报「不足两个期间」** |
| 趋势某期为负 | 条上挂 `is-neg`，方向不丢 |

**`hasHistoryField()` 存在的理由**：要分清两种「画不出趋势」——
「A 还没给」（整块不出现）与「给了但不够两个点」（出来说一句为什么）。
只看 `history().length === 0` 是分不开的。

## 页面 3 · Financial Diagnosis 财务诊断

五个维度，对应 `ratios` 下的五个分组：

| 分组 | 字段前缀 | 指标 |
|---|---|---|
| 成长性 | `ratios.growth.*` | revenue_yoy、net_income_yoy、ar_yoy |
| 盈利能力 | `ratios.profitability.*` | gross_margin、net_margin、roe、roa |
| 偿债能力 | `ratios.solvency.*` | current_ratio、quick_ratio、debt_to_asset、interest_cover |
| 营运能力 | `ratios.efficiency.*` | ar_turnover、inventory_turnover、asset_turnover |
| 现金流质量 | `ratios.cashflow_quality.*` | ocf_to_net_income、ocf_to_revenue、free_cash_flow |

每个指标项的字段：`{ value, unit, formula, threshold, status }`

**色条与结论全部来自 B 的 `status`，前端不自己判断好坏。**

### ⚠️ 雷达图缺口

五维雷达图需要**每个维度的 0–100 归一化得分**。
团队分工说明里没有人负责产出这个字段 —— B 只负责算具体指标，没负责把一组指标压成一个分。

**E 的需求**：请 B 在 `ratios` 各分组下增加 `_score` 字段（0–100）。

例：

```json
"growth": {
  "revenue_yoy": { ... },
  "net_income_yoy": { ... },
  "ar_yoy": { ... },
  "_score": 62
}
```

字段未到位时，雷达图自动降级为文字提示，页面不会崩。

### 版式定案（2026-10-10）

1. **得分不是我们算的**。演示台词就是这个（`DEMO_SCRIPT.md:47-48`
   「我们前端算的……是财务诊断模块给的结论，前端只负责呈现」），
   所以得分要在版面上被看见 —— 雷达图下面那条说明常驻，维度块表头里
   把得分放到 `--fs-xl`，不做成角落里的灰色小字。
2. **两层，不是三层**。原先的结构是「雷达图 → 5 张分组卡 → 5 张明细表」，
   把同一份五维信息讲了三遍；中间那层分组卡既不是雷达也不是明细，
   是纯重复（与页面 5 已删掉的 `.range-line` 同类问题）。
   现在把分组卡的**得分、状态色条、健康分布并进明细表表头**：
   一个维度 = 一块（`.dim-block`），**得分在全页只写一次**。
3. **五个维度块两栏并排（`.dim-grid`）**（2026-10-10 当晚返工）。
   竖着排要滚两屏才看完；更要紧的是五块长得一模一样
   —— 同一个形状重复五次，读到第三块眼睛就滑过去了，这是「阅读体验变差」
   的来源。两栏之后一屏看全五维。窄屏（约 760px 以下）自动退回单栏，
   所以两栏是给演示大屏的，不是硬性的。
3b. **五块必须等高**（2026-10-10 三改）。维度之间指标条数不同（3 / 4 / 4 / 3 / 3），
   块高本来会差一行，两块并排时看着参差不齐。
   靠 `grid-auto-rows: 1fr`（容器高度不定时所有 `1fr` 行都按最高的那一行取值）
   加默认的 `align-items: stretch` 解决，**不给表补空行** ——
   空行会被读成「这个维度缺一个指标」，那是在凭空造数据缺口。
   短的那两块在卡片底部留一点白，那是卡片内边距。
   `.dim-block` 的 `padding` 也从 `.card` 的 24px 收到 16px：
   两块并排后每块只有半屏宽，24px 显空，而且五块等高之后总高度直接影响
   「一屏看全五维」这句话还成不成立。
4. **每块给一句话结论，只报例外**（`.dim-meta`）。
   原先写的是「4 项 · 健康 4 / 关注 0 / 预警 0」——三个数里通常两个是零，
   扫视时是噪声；色条已经把分布画出来了，文字只需要说色条说不出的那句：
   **例外在哪一项**。全健康时才报总数（「4 项指标全部健康」）。
   文字颜色取**本维度最差那一项**的状态色 —— 这是对 B 的 `status` 做翻译，
   没有新增判断。
5. **删掉主行的「阈值」列**（2026-10-10）。阈值在主行写一遍、
   展开行的「判断标准」里又写一遍，同一句话说两遍。
   阈值属于「凭什么这么判」，归展开行；主行只回答「多少、好不好」，
   三列（指标 / 数值 / 健康度）也才装得进半屏宽。
6. **预警 / 关注行左边加一道 2px 状态色**（`box-shadow: inset`，
   不占宽度，两张卡之间三栏仍然对齐）。
   **健康行不涂** —— 对比才是指示，全都涂等于都没涂。
   行上的类是 `st-good` / `st-watch` / `st-bad`，**不复用全局的
   `is-good` / `is-watch` / `is-bad`**：那三个是文字颜色类，
   挂到 `<tr>` 上会把整行文字染色。
7. **本页零 tone**。得分和比率都是水平值，没有涨跌方向。
   颜色只用 status 系统，且完全由 B 的 `status` 字段决定，前端不自己判断。
8. **出处贴在被支撑的数据旁边**（全站原则）：有 `page` 的指标，

9. **雷达图继续用 Chart.js**（不是 DOM）。判断标准见 `js/charts.js` 顶部：

1. **高风险卡片默认展开**。这一页最值钱的就是证据链，不能藏在一次点击后面。
   其余等级折叠。打印 / 导出 PDF 前由 `app.js` 统一展开全部。
2. **本页零 tone**。颜色只用 status 系统（红 = 高风险）。

3. **三层做成「链条」**：左侧一条竖线，三个节点挂在线上。

4. **三层各司其职，不重复**：

   > 数据旁边或下面，并在可点击的文字上挂一个回到原数据位置的链接。

**为什么标尺不用 Chart.js**：浮动条 + 贯穿网格 + 跨行阴影在 canvas 里得写
自定义插件，在 DOM 里就是几个绝对定位的 `div`；而且打印 / 导出 PDF 时
DOM 清晰、canvas 发虚。代价是没有 tooltip —— 所以所有数值都直接写在
行头上，不靠悬停。判断标准写进了 `js/charts.js` 顶部。

### 1. 「本页待实现」开发卡：开关隐藏，不删代码

六页**各有一张**（此前 README 记的是「六页，页面 6 除外」—— **错的**。

**两个设计取舍值得记下来**：

- **DOM 保留，不删节点。** 卡里那些说明是真信息 ——「关键依赖：`report` 的字段结构

**锚点已进测试**：六页各自的 `.dev-card` 数量必须等于 `.todo-list` 数量，
且全站合计 6。少标一页，那个开关就会漏掉一页 —— 而这**在演示现场是看不出来的**，
只有翻到那一页才发现。

### 2. 审计 ④ 裸值：只收零视觉影响的

| 原 | 现 | 处数 | 视觉影响 |
|---|---|---|---|
| `color: #fff` | `--c-on-primary`（新增） | 3 | 无 |
| `border-radius: 999px` | `--radius-pill`（新增） | 6 | 无 |
| `border-radius: 50%` | `--radius-circle`（新增） | 2 | 无 |

三处 `#fff` 压在 `var(--c-primary)` 实底上（`.btn-primary` / `.sug-tag` / `.v-conc-name`），

审计 ④ 的读法里写明了「已知保留，不是漏收」—— 免得下次跑审计的人去追。

和上面把判读线从 1.15 调到 1.14 是同一个道理。

## 共享段 · 配色 / 玻璃 / 面板 / 字体定案（2026-10-12）

这一轮不是「美化」，是接着上一轮字号阶梯往下解决的**同一个问题**。
上一轮的投诉是「一堆没有分辨度的数据让人没有仔细看的耐心」，
上一轮用**字号阶梯**解决了「层级不分」；这一轮解决**落点**——
改版前是一张平均用力的白纸，每个数字长得一样重，眼睛没有可落脚的地方。

同日四轮迭代，每轮都由实际反馈推动，下面按**定案**记，不按时间记。

### 1. 三色分工：灰蓝 / 黑 / 橙

**问题**：改版前 `--c-primary` 一个蓝在页面 4 被引用 13 次、页面 5 引用 10 次，
导航、链接、大数、按钮、标尺全是它。**什么都用它，等于什么都没强调。**

**判据三条，互斥：**

| 色 | 令牌 | 判据 |
|---|---|---|
| 灰蓝 | `--c-primary*` | **结构 / 可点 / 参考**。凡是组织版面而不是喊的，都归这里 |
| 墨黑 | `--c-ink` | **内容焦点**。要读的那个数、那个词。黑「响而不着色」，可重复出现而不变噪 |
| 橙 | `--c-watch*` | **强调 = 可行动 + 需关注**。全站唯一暖色 |

**橙的预算是这套分工的命根子：每屏最多 1–2 处。** 限量是一色一义的前提。

**净效果**：页面 4 那 13 处蓝、页面 5 那 10 处蓝，大部分退成灰蓝；
橙只出现在数据说「要看」的地方。60+ 处出处链接**必须**留在灰蓝 ——
它们全变橙就是灾难，等于回到「没有分辨度」。

**两条被否掉的诱人选项**（都有人会想这么做，记下来免得下次再想一遍）：

1. **`.fin-bar` 比例条变橙** —— 不行。`render.test.js` 钉着它必须含 `--c-bar`
   且不得出现任何 status / 橙令牌。比例条是**结构**不是**警报**。
2. **页面 2 的图表加橙色强调线** —— 页面 2 根本没有 Chart.js 图表，
   它的「图」是 DOM 条形（`.trend-*` / `.fin-bar`），而这两族同样被红线禁止用橙。
   这条**至今未定**：要么放开 `.trend-*` 红线，要么真加一张 Chart.js 折线图，
   要么挪到别页。⚠️ **仍未拍板。**

### 2. 橙的语义被**扩宽过一次**（这条比色号重要）

第一轮的定案是「橙 = 警报色」，`.btn-primary` 走黑。**当天就被推翻**：
反馈「我选择橙色作为主色的意思是，我希望部分按钮等可以是橙色」。

所以橙的语义从「警报」扩宽成「**强调 = 可行动 + 需关注**」，
`.btn-primary` 改成橙底（`--c-watch-ink` 实底 + 白字，5.6:1）。

**但预算没跟着放宽。** 扩宽的是**含义**，不是**用量** ——
一个色可以有两个相近的意思，但绝不能到处都是。这个区别是这一轮
最容易搞错的地方：语义扩宽 ≠ 可以随便用。

#### 2b. 第九轮：橙面配什么字（**这条比色号重要，也是同一个坑的第三次**）

> ⚠️ **本节的选择（`--c-watch-on: #502e00`）已被第十轮推翻。**
> 第十轮她指定「橙面内部字体换成白色」，改成 `--c-on-primary`，
> 该令牌已删除。**§2b 里「不选白」的那半段结论作废，但「问题在色相不在明度」
> 这个诊断仍然成立** —— 白字只是绕开了「配什么深色」这个问题本身。
> 第十轮的完整取舍见下面 **§2c** 与文末「第八 / 第九 / 第十轮」一节。


反馈原话：「我的主色之一是橙色，主要作为按钮的颜色在黑灰蓝等颜色中起到
缓解视觉疲劳的作用，但是，**现在橙色和黑色的按钮色彩搭配的很不好**。」

这句话把前几轮的一个判断**直接推翻**了。第六到第八轮一路写的是
「面上配深墨 `--c-ink` = **8.0:1**，比原来更好」，把它当成论据 ——
**8:1 只是「够清楚」，不是「好看」**。她否的恰恰是好看那一半。

量因（可复算，不是形容词）：
`--c-watch #fa9205` 色相 **34.5°**，`--c-ink #0f151d` 色相 **214.3°**，
相差 **180°** —— 色轮上的正对面。一对互补色同处一块不大的色块上，
读起来是**警示标签**（黄黑条纹就是这对），它喊「注意」，
而按钮要的是「可以点」。

**改法不是在明度上再调**（明度一直达标，问题不在那儿），
而是把字搬到**橙自己那条色相线上**更深的一档：

| | 值 | 色相 | 用在哪 | 对比 |
|---|---|---|---|---|
| `--c-watch` | `#fa9205` | 34.5° | 面（按钮底 / chip 底 / 色条 / 边框） | —— |
| `--c-watch-ink` | `#aa6300` | 34.9° | 字，压**浅底**（`.warn-title` / `.is-watch`） | 白底 4.67:1 |
| `--c-watch-on` | `#502e00` | 34.5° | 字，压**橙面**（主按钮 / 两种胶囊） | 橙底 **5.30:1**（hover 后 4.68:1） |

规则一句话：**暖底配暖字，橙面上不再出现冷的墨黑。**

★ 三个要同时改的地方（少改一处就是「同一张脸两种字」）：
`.btn-primary`、`.risk-card.sev-attention .sev-chip`、`.status-chip.is-watch`。

★ 对比度从 8.0:1 收到 5.3:1 **不是退步**：WCAG 的 4.5:1 是「看得清」的门槛，
在**实底大色块**上继续往上堆只会发闷，按钮不是正文。
下限仍要守住，所以 `render.test.js` 新增一条断言同时钉两件事 ——
**色相差 < 8°**（拦「又滑回冷墨」）和 **≥ 4.5:1 且 hover 压暗后仍 ≥ 4.5:1**
（拦「为了好看压暗到看不清」）。
只钉对比度是不够的：被否掉的那版对比度是**达标**的，它栽在色相上。

#### 2c. 第十轮：橙面上的字改成**白**，以及它换来的那个 2.29:1

反馈原话：「**橙色按钮/标注的内部字体换成白色**」。

第十轮**没有**去找一个「更好的深色」，而是绕开了这个问题：橙面上的字用白。
白在这套 UI 里不是新东西 —— `--c-on-primary: #ffffff` 的既有角色就是
「压在实底上的白字」（`.sug-tag` 的灰蓝实底、深色侧栏的导航文字都用它）。
所以这一轮**没有新增令牌**，反而是**删掉**了第九轮的 `--c-watch-on`：
它唯一的用户就是这三处橙面，改成白之后它成了死令牌。

##### 代价是实测的：白 on `#fa9205` = **2.29:1**，低于 WCAG AA 的 4.5:1

这是**知情的取舍**，不是漏算。所以更要紧的是下面这一句：

> **想让它达 AA，只有一条路 —— 把橙面压深。**
> 白字要够 4.5:1，橙面的相对亮度必须 ≤ 0.183；
> 在这个色相上，那意味着 `#b35f00` 这一带的**褐色**（+白 = 4.61:1，确实达标）。
> 代价是「按钮橙」不再等于「色条橙」，而那正是她第六轮亲口否过的东西。

实机对照过三案（1600 宽，同一页同一处，×3 放大判读）：

| 案 | 橙面 | 字 | 实测对比 | 判读 |
|---|---|---|---|---|
| 第九轮（旧） | `#fa9205` | `#502e00` | 5.30:1 | 达标，但橙面发闷、像「烤过头」的按钮 |
| **A（本轮采用）** | `#fa9205` | `#ffffff` | **2.29:1** | 橙仍是那个亮橙，白字清亮 —— 代价是低于 AA |
| B（未采用） | `#b35f00` | `#ffffff` | 4.61:1 | 达标，但橙掉亮度、**和色条不再同色** |

选 A。理由不是「好看优先」，而是 **B 会同时推翻她两条已定的要求**
（第七轮她指定了 `#fa9205`；第六轮她要求「全篇只有一个橙」）。

★ 顺带记一笔**同一道算术的两个方向**：
- 第六轮（README §4 / #123）：橙**当白底小字**，越亮越差 → 所以橙分「面 / 字」两档。
- 第十轮（本节）：橙**当白字的底**，也是越亮越差 → 这次没有再拆色号，而是接受。
  **一个色阶能同时满足「面够亮」和「字达 AA」是不存在的**，只能选一头。

##### 守卫跟着改了：不再钉对比度，改钉**取舍本身**

第九轮那条断言钉的是「色相差 < 8° + 对比 ≥ 4.5:1 且 hover 后仍达标」。
第十轮把对比那半条**去掉**了 —— 2.29:1 是取舍，硬钉 4.5 只会让它永远红，
而**一个永远红的守卫比没有守卫更糟**，人会开始无视它。

改钉的两件事各有各的对手：

| 断言 | 对手 |
|---|---|
| 三处橙面的字都必须写 `color: var(--c-on-primary)` | **半截改法** —— 只把其中一处改回深色，同一张脸就又出现两种字 |
| `--c-watch` 必须仍是 `#fa9205` | **为了凑对比去压深橙面** —— 一旦有人这么干，「按钮橙」和「色条橙」裂成两种 |

##### 附带修掉的一个真 bug：守卫读的是**注释里的色号**

写这一轮的守卫时才发现：第九轮那条断言**当时是红的**。

`render.test.js` 抽令牌用的是 `base.css` 的 `:root` 原文 + 一条正则。
而 `base.css` 的注释里有一句：

```
接替原来的 --c-watch: #c9922f（黄）。
```

它长得和一条真声明一模一样，正则把它当成 `--c-watch` 的**第一条**匹配，
而取值用的是 `find()`（取第一条）⇒ `tok("--c-watch")` 返回的是
**已经退役的 `#c9922f`**，不是活的 `#fa9205`。

于是第九轮那条断言的三个数全是错的：

| 量 | 按注释里的 `#c9922f` 算（= 守卫实际算的） | 按活的 `#fa9205` 算（= 它以为在算的） |
|---|---|---|
| 与 `#502e00` 的对比 | **4.41:1** ← 低于它自己的 4.5 门槛 | 5.30:1 |
| hover 压暗后 | **3.92:1** ← 同样不达标 | 4.68:1 |
| 色相差 | 4.1°（仍然 < 8°，所以这一半是过的） | 0.0° |

也就是说：**它当时就该红** —— 按它自己的数字，两个对比值都没过关。
修法是抽令牌前先 `stripComments()`。**一个读错值的守卫比没有守卫更糟**，
它给的是假的安全感 —— 这条已记进 `docs/EDGE_CASES.md` #133。

### 3. 毛玻璃

**配方**（`css/components.css` 卡片族一处写）：

```css
background: var(--c-glass);            /* rgba(255,255,255,0.60) */
border: 1px solid var(--c-glass-line); /* rgba(255,255,255,0.70) 白色描边 */
box-shadow: var(--shadow), var(--shadow-inset);
backdrop-filter: var(--glass-blur);    /* blur(16px) saturate(1.4) */
```

**四个技术要点，都不是风格选择：**

- **描边用白色半透明而不是灰线**：玻璃的边是**光**，不是墨。
- **alpha 必须 < 1**，否则 blur 没有对象。0.60 是低限：低于 ~0.45 在浅渐变上
  看不出磨砂，高于 ~0.70 失去玻璃感。
- **`-webkit-` 前缀必须有**（Safari / 旧 Chrome）。
- **不嵌套玻璃**。这一条有两个后果，第二个是这轮才踩到的，见第 4 节。

**走过的一段弯路，值得记下来**：第一版是「白玻璃铺在近白背景上」——
差值只有 3%，肉眼为零，反馈直接打回：「卡片看不出来是玻璃卡」。
根因是**背景太浅，玻璃没有东西可透**。修法是把背景加深（不是动 `--c-glass`）。
后来又按反馈从 11% 一路调浅到 5.5% —— 因为把背景加得太深会「脏、平」。

> **记住这对关系：背景深浅和玻璃可见度是反比。**
> 玻璃又看不见了，就**抬背景的值**，不要去动 `--c-glass`。

**另一个坑**：`body::before` 那两团光晕原来是**橙**的，被反馈打回
「底色的橙色有点脏」。**不只是好不好看** —— 背景铺一层橙等于把橙稀释成底色，
「橙 = 强调」立刻失效。删掉后冒出「背景太平」（纯线性渐变没有光照层次），
所以补回两团**白色**柔光：白色不改色调，也不占强调色的名额。

### 4. 两块面板（2026-10-12 第四轮）

反馈：「把左侧边栏和主题内容做成两个面板，面板之间需要有明显的分割，
面板方形折角的地方做成圆弧状」。

**「明显的分割」用的是缝，不是线。** 上一轮试过靠 1px 描边区分左右两块，
投影仪上直接并成一片 —— 一条线的对比度扛不住远距离。改成 `body` 加
16px `padding` + `gap`，**背景渐变从缝里透出来**。可见度高一个数量级，
而且不消耗任何颜色预算。

**圆角新开一档 `--radius-xl: 20px`，只给面板用。**
原来的 `--radius-lg: 12px` 是给卡片定的，铺到 100vh 高的面板上折角显得很方。
一档尺寸一个用途，混用会让「大圆角 = 面板」这个信号失效。

**★ 面板不是玻璃 —— 这是这一轮唯一需要解释的结构性取舍。**

最外层本来是背景渐变，卡片是玻璃，**一层**。现在中间插进一层面板，
如果面板也用 `0.6 白 + blur`，就变成**玻璃套玻璃**：

```
背景渐变 → 玻璃面板(0.6 白) → 玻璃卡片(0.6 白)
```

两层 0.6 白叠完，卡片和面板只剩 **2–3 个色阶**的差，肉眼为零。
「卡片看不出来是玻璃卡」会被原样复现，而且**更糟 —— 连面板都看不出来**。
加上测试钉着「卡片必须是半透明白底 + backdrop-filter」，只能动面板、动不了卡片。

**正解是让面板比卡片暗。** 面板用 `--c-surface-2`（蓝灰），
卡片是白玻璃压在上面，自然亮 15–21 个色阶。层级变成三层，每层都看得见：

```
背景渐变（只在 16px 的缝里露出来） ＜ 面板（蓝灰） ＜ 卡片（白玻璃）
```

和参考图是同一个层次法：**靠明度差分层，不靠线。** 一句话记法：
**外壳玻璃，内容垫板。**

复用 `--c-surface-2` 而不是新开令牌，有两个理由：它的语义本来就是「底板」
（本来就用在内层 `.kv-cell` / `.note` / `.ratio-row:hover`），面板是最外一层底板，
同一个意思；而且不再造一个几乎同值的颜色，**「没有任何两个含义不同的令牌同值」**
这条不变式不会被破。

> 附带好处：`.main` 不做 `backdrop-filter` 还顺手避掉一个坑 ——
> `backdrop-filter` 的祖先会成为**固定定位子元素的包含块**。
> 页面 4/5 的溯源弹窗（`.popover`，全站唯一的 `position: fixed`）
> 就会被困在面板里。没加，所以没事。

### 5. 字体

> ⚠️ **本节下面的「定案」在 2026-10-13 第五轮被实测推翻了一半，先读那节再读这里。**
> 关键两条：① 演示机**没有注册** `"Noto Sans SC"` 这个族名，
> 所以「换上之后 37 处 500/600 会真的渲染出来」**从未发生** —— 全站中文一直是微软雅黑；
> ② `Bahnschrift` 是**窄体且不响应字重**，拿它当数字字体反而考出了「同一行数字
> 看着像另一个字号」。完整证据与量法见文末
> **《2026-10-13 定案（第五轮）：字体实测 · 间距加密》**。

**改之前先查清楚「到底在渲染什么」，结论和看起来的完全不一样：**

| 项 | 表面 | 实际 |
|---|---|---|
| 中文 | Microsoft YaHei | 一样 |
| 数字 | `DIN Alternate` | **Arial**。`DIN Alternate` 是 **macOS 独有**字体，Windows 上根本不存在，一路落到 Arial。全站 `.num` / `.metric-value` / `.kv-val` / `.fin-value` / `.dim-score` 一直是 Arial 在渲染 |

**「刻板」的机械原因不是字形，是字重断档：**

微软雅黑只有 Light / Regular / Bold 三档，**没有 500 / 600**。
而全站写了 500 × 10 处、600 × 27 处。按 CSS 字重回退规则，
缺失的 500 取 400、600 取 700 —— 这 **37 处全部空转**：

- `.nav-title`(500) 和正文一样粗；
- `.nav-link.is-active .nav-title`(600) 和 `.brand-mark`(700) 一样粗。

层级实际只剩 400 / 700 两档硬跳，中间没有过渡。
**这才是「一眼看过去全是一个调子」的来源，不是雅黑长得难看。**

**定案**：

```css
--font-sans: "Noto Sans SC", "Microsoft YaHei", "PingFang SC", …;
--font-num:  "Bahnschrift", "DIN Alternate", "Segoe UI", …;
```

- `Noto Sans SC` 是**可变字体，真实 100–900 九档**。换上之后那 37 处
  **一个字符都不用改就生效**。换字族的第一目的是**让已经写好的字重层级真的
  渲染出来**，字形变化（比雅黑更圆、更中性、字面略宽）是顺带的。
- `Bahnschrift` 是 Windows 10 起自带的**可变字重 DIN**，就是 `DIN Alternate`
  的 Windows 正牌同血统字体。顺序写成 `Bahnschrift → DIN Alternate` 而不是
  倒过来：Windows 取前者、macOS 上前者缺席自然落到后者，**两边都拿到 DIN**。
- **回落链是保险不是凑数。** 演示机没装 `Noto Sans SC` → 自动落到微软雅黑，
  **和改之前一模一样，不会更差**。本项目 `file://` 双击打开、不引任何在线字体
  （硬约束），所以只能用系统字体，回落链就是唯一的安全垫。

**同步要求**：`js/charts.js` 的 `PALETTE.font` 必须跟着 `--font-sans` 走，
否则会出现「页面的字换了、图上的字还是雅黑」。

### 6. 风险卡：等级色从「一条边」改成「整卡染色」

反馈：「风险卡片去掉左侧的红/橙/绿线，去掉上方的白线，
统一改为预警严重程度下对应的红/橙/绿透明渐变毛玻璃效果」。

**「上方的白线」有两条来源，以为删一条就够了是这里最容易踩的坑：**

1. `border: 1px solid var(--c-glass-line)` —— 白描边，四边都有，顶上那条最显眼；
2. `box-shadow` 里的 `--shadow-inset`（`inset 0 1px 0` 白色内高光）—— 正压在顶边。

**顺带统一了三级**：以前是「高风险 4px 边 / 关注 1px 边 / 正常 2px 边」三种写法，
等级差别实际靠边的**粗细**在传达 —— 而 1px / 2px / 4px 在这个尺寸上根本看不出来。
现在三级结构完全一致，只换色相，差别只由颜色承担。

**删掉边之后等级信息一点没少**，这是升级不是妥协：
一条 4px 的边在快速滚动时很容易被漏掉，**整张卡染上颜色则不可能看不见**。

**新定的一条不变式：同级不同色，浓度必须齐平。**
三级渐变的端点一律 `-2 = 0.20` / `-3 = 0.03`（`--c-{bad,watch,good}-bg-2/-3`）。
颜色的浓淡天然会被读成轻重 —— 橙要是比红浓，读者就以为「需关注」更严重。
**测试「红/橙/绿三级渐变的浓度逐档一致」会强制这一点**，
所以将来要调淡橙色，必须三级一起调。

**两处连带影响（不处理会静默出错）：**

- **降级块**（§18）：原来直接 `background: var(--c-surface)` 会把渐变层一起冲掉，
  三级全变白卡。改成只换底下那层（`--sev-base`）。
- **打印段**：`.risk-card` 在「平铺成白面」的名单里，同样会抹平等级色。
  补一条把渐变贴回去，**靠源码顺序取胜 —— 注释里写了「别挪位置」**。

### 7. 这一轮挖出来的四个真实缺陷

都不是「不好看」，是**本来就是坏的**：

| 缺陷 | 真相 |
|---|---|
| 字体 500/600 空转 | 雅黑没有这两档，37 处回落成 400/700 |
| 数字一直不是 DIN | `DIN Alternate` 在 Windows 不存在，落到 Arial |
| `.dim-grid` 上下两处间距漏洞 | 容器不收边距又没有兄弟认账，页面 3 两次卡片**直接贴上** |
| 风险卡等级差等于没传 | 靠 1px / 2px / 4px 的粗细区分，根本看不出 |

**第 3 条值得单独记一条规律**：凡是「父子之间有一方被显式归零」的地方，
**都要检查对面那一方**。这个容器已经踩过两次 —— 先漏 `margin-bottom`（维度块和
下方卡片贴上），后漏 `margin-top`（说明条和第一排卡片糊在一起）。

是让下一个人花时间去确认它到底还有没有在用。

### 2. 页面 3：status 的语义决定这一页长什么样

D 给的是 `status: ok / not_evaluable / not_meaningful`，含义是
**「这一项算不算得出来」**，不是「好不好」。所以：

- 算得出的**不上色**（`ok` 与 `not_meaningful` 都不需要动作）——
  给 35 行挂同一个「正常」标签，等于挂满等于没挂。
- 橙**只**出现在「待核验」上。**橙出现即「这里有活要干」。**
- 表头右上角放的不是得分，是「N 项待核验」—— 位置和分量都在，
  只是说的从「多少分」变成「几项要补」。
- 结论句只报**例外**（「14 项指标中 4 项待核验」），全算得出时才报总数。
- ⚠️ **待核验行左侧那道 2px 橙，2026-10-13 才第一次真的画出来**：
  CSS 写的选择器是 `.ratio-row.st-watch` / `.st-bad`，而页面挂的类名是
  `st-not_evaluable`，两边对不上，选择器**一直是死的**，只是没人对过
  DOM 里的类名。现在测试里钉了「选择器必须与 `addRow()` 拼出来的逐字相同」。

### 3. 页面 3：比值项的 `page` 只给得出 2/68，**不写提示条**

真数据里 68 项有 2 项带 `page`（现金流质量的 ocf @6、capex @13），
其余 66 项是 `null`。**这是对的** —— 比率由几个科目算出，本来就不对应某一页。

- 页面按「**有则渲染、无则整格不放**」处理：有 `page` 的行在指标名下挂一行灰字可点页码，没有的行**连那个元素都不建**（不是留个破折号占位）。
- **不写「还差 N 项」的提示条。** 缺的是**可选字段**，不是缺口；
  在 66 行上各挂一句提醒，等于把「正常」说成「缺陷」。
- ★ 但 D 若哪天想支持「点开看是哪几个科目」，要的是 **`inputs`（已有）**，
  不是 `page`。两个标准混用的结果是读者以为只有那两项能溯源。

### 1. 百分比精度：统一到 **2 位**（E 往 D 靠）

| | 之前 | 之后 |
|---|---|---|
| D 的 memo | `"13.33%"` `"34.46%"` `"-1.21%"` `"50.00%"` | 不变 |
| E 的 `fmt.percent` / `fmt.signedPercent` | `"13.3%"` `"34.5%"` | `"13.33%"` `"34.46%"` |

**判断依据**：同一个 ROE 在页面 3（走 `ratioValue`）和页面 6（照抄 D 的 memo）
上必须长得一样，否则读的人会以为其中一处算错了 —— 这和 `money()` 要补千分位
（E 出 `1688.38`、页面 6 出 `1,688.38`，同一个数两个长相）是**同一类毛病**。

**谁跟谁**：E 跟 D。理由是 `docs/INTERFACE_CONTRACT.md` 开头那句
「字段名以 D 的为准」—— D 是口径的生产方。而且 E 这边已经为元→亿元
跟过一次 D，再跟一次不增加新的依赖方向。

**只动两个函数的默认值**，不动 `fix()`：`fix()` 被 `num` / `signed` /
`multiple` / `times` / `days` 共用，那些的单位是倍 / 次 / 天，跟百分数不是一回事，
一起改会顺手改掉十几种显示。

**连带**：页面 5 有 10+ 处直接调 `fmt.percent`（WACC / 永续增长率 / 敏感性矩阵
表头与格子 / 三情景权重），一并变 2 位。矩阵格子从 `-12.3%` 变 `-12.34%`，
列宽够，没挤坏。

### 4. 页面 6：报告纸放宽 + 摊平卡改成显式类

**`.paper` 46em → 56em**（基准 14px，≈644px → ≈784px）。
46em 是按**纯正文的阅读行长**定的，但那张纸里不止有正文：
四张风险卡整宽堆叠，每张带一条三层证据链和一个六列 `.mini-table`，
644px 下六列表挤成一团；纸本身在 1440 的屏上只占内容区六成不到，看着像一栏不是一页。

**为什么不再宽**：中文的行长就是字数，1em ≈ 一个字。56em ≈ 一行 56 个汉字，
是这份文档里最长的一段正文（免责声明）还能读的上限。要更宽就得单独给正文
设一个窄度量 —— 那是另一件事，等人真的觉得读不动了再说。

**摊平卡：`.paper .risk-card` → `.risk-card.is-flat`**。两条理由：

1. **意图要写在调用点**。原来「这张卡要摊平」在 JS 里完全看不出来 ——
   `p6-memo.js` 的 `riskCard()` 只写了 `risk-card is-open`，摊平是 CSS
   在后面偷偷补的。谁把卡片挪出 `.paper`，样式会静默变回去，
   没有一处代码能提示他。
2. **后代选择器把「在哪」和「长什么样」捆死了**。这张卡要不要摊平取决于它
   **压在什么底上**，不取决于它爹的类名是不是叫 `paper`。

名字取 `is-flat` 而不是 `is-on-paper`：它描述**渲染结果**（无浮影、无玻璃、
一条发丝线），跟其它 `is-*` 修饰类一个路子；「为什么这儿要摊平」是调用点
该写清楚的注释。

### 7. 补记：页面 2 白屏（同日，收尾时发现）

定案都落地、387 全绿之后，**在真浏览器里打开页面 2，整页白屏**：

```
Failed to execute 'add' on 'DOMTokenList': The token provided must not be empty.
```

**两个判断值得留档：**

**① 这不是偶发，是必挂。** `p2-overview.js` 的大数卡写的是
`c.classList.add(fmt.statusClass(item.status))`，而 `statusClass` 对
**「不需要上色」的那几档**（`ok` / `found` / `not_applicable` / `not_meaningful`）
返回的是**空串**。真数据里 `ok` 有 35 项、`found` 有 16 项 ——
也就是说这一页**从来就打不开**，不是这次改坏的。

**② 空串不是「什么都不做」，是抛异常。** 这是最容易记错的一条：
`classList.add("")` 在浏览器里直接 throw，跟「加了个没用的类」完全不是一回事。
凡「返回字符串、可能为空、直接喂给 DOM API」的地方，都要单独问一句
空的时候是抛还是无操作 —— `classList` / `setAttribute` / `querySelector` 三者各不相同。

**修法：** 新增 `ui.addClass(n, cls)`（`app.js`），空类名直接不进 `classList`。
`p2-overview.js` 与 `p6-memo.js` 两处改走它 —— 后者是同一个坑：
`severityClass` 对未映射等级也返回空串，原来那句 `if (code)` 只挡了
「标签认不出来」，挡不住「标签认得、等级没映射上」。

**为什么不改 `statusClass` 的返回值：** 那个空串是**有意的信号**
（空串 = 这一档不上色，调用方靠它做判断）。该固定的是「空类名不能进
`classList`」——那归 DOM 层管，所以修在 `ui.addClass`。

**★ 真正该记的是：它逃过了 387 条断言。** 唯一原因是**测试桩比浏览器宽松** ——
桩里的 `classList.add` 写着 `if (c && ...)`，把空串静默吞掉了。
所以这一轮的动作顺序是**先把桩改严（复现）→ 再修**，不是反过来。
桩现在照真浏览器对空串 / 含空格抛异常；`render` 从 249 涨到 **261**（+12 条回归，
含一条「桩的保真度自检」—— 谁哪天把桩改回宽松，那条会立刻红）。
教训记在 `docs/EDGE_CASES.md` #98。

### 8. 补记二：「商誉」不是缺口，是「不适用」（同日）

修完白屏紧接着发现**提醒条一直在说谎**：页面 2 的商誉缺一项 `core`，
于是控制台常挂一句

```
【财务概览】缺 1 项：商誉 · 找 A
```

但 D 早就在那一格上写了 `status: "not_applicable"` —— 意思是
**年报的资产负债表上根本没有「商誉」这一行**。所以这不是「A 还没抽」，
是「这家公司没有」。E 在催 A 补一个不存在的数，A 接下来只会去编一个。

**一条指错的欠账比没有欠账更坏。** 这是本轮定下的判据。

**两处改动，同一条规矩：**

| 层 | 改法 |
|---|---|
| `dataLoader.financialGroups()` | 祖先对象标了 `not_applicable` → **整行不画**（表头/列宽/行数全自动跟着走） |
| `contract.check()` | 新增第三遍：这一族路径记成 `na`，不进提醒条、不进 `byOwner` 欠账清单 |

**★ 最要紧的一行判断：判据落在 `status` 上，不是 `value === null` 上。**
按 `value` 判会把「上游没抽到」一并放行，那样这一页就再也说不出
「这一格是空的」—— 而「数字必须可验证」正是本页存在的理由。

## 2026-10-13 定案（第五轮）：字体实测 · 间距加密

> **轮次编号是全项目共用的**（`css/*.css` 的注释也用它）：
> 第四轮 = 2026-10-12 的风险卡「整卡染色」改版；本轮 = 第五轮。
> 本节标题里的轮次与 CSS 注释里的「2026-10-13 第五轮」是同一轮。

### 起因

你的原话两条：「字体和字之间、板块之间的间距还是又过于靠近」，
「字体不好看，大小很奇怪」。**第二条不能靠感觉改** —— 上一轮
「换上 Noto Sans SC」之后就以为解决了，这次先查清楚屏幕上到底在渲染什么。

### 一、量法（这一步本身是这一轮最值钱的东西）

`file://` 下没法装调试工具，用 headless Chrome 起一个探针页
（`tools/probe-harness.html` 的「② 字体实测」段就是它的定型版）：

- 用 `document.createElement("span")` + `getBoundingClientRect().width` 量渲染宽；
- 配一个**保证不存在的假字体名** `"__NoSuchFontZZZ__"` 当基线：
  **实测宽 == 基线宽 ⇒ 这个名字根本没解析到**，落到了回落链末端。

两个必须记住的坑（否则会得出完全相反的结论）：

1. **不能用汉字宽度判字重。** CJK 表意字的 advance width **恒为 1em**，
   与字重无关 —— 用「贵州茅台」测，任何字重都是 400px，看起来像「字重全无效」。
   必须用**拉丁串**（探针里用 `Wgm1688`）。
2. **canvas 的 `measureText` 不认 `font-variant-numeric`**，`getBoundingClientRect` 认。
   要判 `tabular-nums` 是否生效只能走 DOM。

### 二、查出来的两条（这才是「字体不好看」的真因）

**㈠ `"Noto Sans SC"` 在这台演示机上没有被注册。**

拉丁串 `Wgm1688.38` 在 `"Noto Sans SC"` 下量到 595.88，
在假字体名 `"__NoSuchFontZZZ__"` 下**逐字节相同也是 595.88** ⇒ 未解析。

真因：本机装的是 `Noto Sans SC Medium (TrueType).otf` / `... Light (TrueType).otf` /
`NotoSansSC-VF.ttf`，**注册名是带字重的**（`"Noto Sans SC Medium"`），
**整族名 `"Noto Sans SC"` 没被注册**。所以：

> **全站中文一直是微软雅黑。上一轮那次「换字族」从未生效，
> 而 §5 里那 37 处 500/600 到今天仍然全部空转。**

**那能不能改用 `"Noto Sans SC Medium"`？不能。** 实测它虽然是「Medium」，
却是个**单一静态字面** —— 用拉丁串测 weight 300/400/500/600/700/800/900
渲染宽**完全一样（互异 1/7）**。换上它会把全站 37 处 500/600
**从「回落到 400/700」压平成「全部同一个宽度」**，比现状更糟。

（同一次实测里：微软雅黑字重互异 **3/7**（400↔500 同、600↔700 同），
所以它至少还有 Light/Regular/Bold 三档可分辨。）

**㈡ `Bahnschrift` 是窄体，且不响应字重。**

| 量项（@100px） | Bahnschrift | 微软雅黑 |
|---|---|---|
| `1,688.38` 串宽 | 364.66px | 400.0px |
| 汉字「贵州茅台」宽 | 400px | 400px |
| 数字串 / 汉字宽 | **91.2%** | 100.0% |
| 数字高 vs 汉字高 | 89 : 94（**矮 5%**） | — |
| 字重互异 | **1/7** | 3/7 |

⇒ 同一行 `1,688.38 亿元` 里，数字**又窄一档又矮一档**，看着就像另一个字号；
且 `.metric-value`(700) / `.fin-value`(500) 这些字重在数字上**从来没生效过**。

### 三、定案

**改法不是「再找一个更好看的数字字体」，而是「不再让数字和正文用两个字族」。**
层级改由**字号 + 字重 + 颜色**三样做。

```css
--font-sans: "Noto Sans SC", "Microsoft YaHei", "PingFang SC",
             "Hiragino Sans GB", "Source Han Sans SC", sans-serif;
--font-num:  var(--font-sans);   /* ← 与正文同族 */
```

- 写 `var(--font-sans)` 而不是**抄一份字体栈**：抄一份会造出两个「含义不同但值相同」
  的颜色式陷阱（这里是字族版），违反「零重值」这条不变式，也埋下「改了上面忘了下面」。
- **令牌名 `--font-num` 保留不删**：六组选择器还在引用它；而且
  `.num … { font-variant-numeric: tabular-nums }` 那一整条规则里
  **`tabular-nums` 仍然是实打实生效的**，只有 `font-family` 那半句变成了空操作。
  探针的「纯数字必须与正文同族」判据也还在跑 —— 要删得两边一起删。
- 字体回退链因此变窄（`Helvetica Neue` 已不在链上），
  链上最坏情况就是微软雅黑 —— `.board-table` / `.fin-table` 的 `min-width`
  重扫一遍仍然成立且更宽裕（见 `css/components.css` 三处注释）。

## 2026-10-13 定案（第六轮）：橙色统一与提亮 · 折叠修复 · 段落间距

这一轮的输入是五条反馈。**先把结论放前面**：五条里只有两条是审美偏好，
另外三条的根因分别是**一个从未生效的机制**、**一处被当正文渲染的注释语法**、
和**一处数据覆盖边界**。找到根因再改，改的东西比「调一调版式」少得多。

### 一、橙色：一个色号，靠「面 / 字」分工满足两个互相矛盾的要求

你的两条要求是 **（a）全篇必须是同一个橙、（b）这个橙要更亮**。
它们和第三个没说出口的要求 **（c）橙有时得当字用** 是**互相冲突的**：

| 橙的值 | 白底当字的对比度 | 判定 |
|---|---|---|
| `#a94e0b`（第三轮） | **5.56:1** | 当字过关，但在低明度上掉彩度，**看着偏褐** |
| `#e2761e`（第四轮） | **3.07:1** | 只到 WCAG 最低档附近 |
| `#f2831a`（本轮） | **2.61:1** | **当白底小字不达标** |

**橙越亮，当白底小字越差** —— 这不是调参能调出来的，是亮度本身决定的。
所以解法不是取中间值，是**分工**：

```css
--c-watch:      #f2831a;   /* 亮橙：只当面 —— 按钮底 / chip 底 / 色条 / 边框 */
--c-watch-ink:  #b85c05;   /* 深橙：只当浅底上的字 —— 同色相里最鲜艳且仍达 AA */
```

- **面上一律配深墨字 `--c-ink`**：亮橙 × 深墨 = **7.0:1**，
  比原来的「深橙配白字」**更好**。三处面积最大的橙面全按这个改：
  `.btn-primary`、`.status-chip.is-watch`、`.risk-card.sev-attention .sev-chip`。
- **白底橙字全站只剩两处**：`.warn-title` 与 `.is-watch`（4.60:1）。
  ★ 刻意**没有**把 `.warn-title` 也改成「橙底深字」—— 它是一条铺满宽的横条，
  铺满的大橙底会把橙的稀缺性打掉（橙的预算见下）。
- `--c-watch-ink` **不是第二个橙**，是同一个色相在「当字」这个用途上的唯一可选档。
  `:root` 里没有任何两个**含义不同**的令牌同值，这条不变式由测试钉着。

**一个代价要认下来**：橙变亮之后，它在**浅橙底纹**（`--c-watch-bg` 0.12 / 0.20）
上的「格内文字」也不再是橙字，一律走墨。视觉上橙从「有颜色的字」
退成「有颜色的面」——**这正是这次要的**：橙负责吸引眼睛，不负责承载阅读。

> ⚠️ **下面的色号已被第七轮取代**（她指定了 `#fa9205`）。**结构不变**，
> 只有两个值换掉、对比度重算。见本文档「第七轮」一节。

### 二、页面 3：折叠机制从来没生效过（真因）

反馈原文是「不太好看、可读性不高」。查下去发现**不是版式偏好**：
`dimBlock()` 把其余 7–14 行 `push` 进 `folded`、点击时给它们 `is-open`，
**但 CSS 里没有任何规则把它们收起来**（`.ratio-row.is-open` 只改背景色，
`.ratio-detail` 是「点开看公式」的**另一件事**）。于是五个块平铺 10–18 行，

### 一、橙：采用她指定的 `#fa9205`，配对深档同色相

第六轮报的是「橙要更亮」，这一轮她直接给了色号。**不再自己挑亮度**，采用 `#fa9205`，

| 令牌 | 值 | 色相 / 饱和 | 用途 | 对比度 |
|---|---|---|---|---|
| `--c-watch` | `#fa9205` | 34.5° / 96% | **面**（按钮底 / chip 底 / 色条 / 边框） | 配深墨 `--c-ink` = **8.01:1** |

- **两个值的色相差 0.4°**。这是这一轮唯一需要算的东西：
  第六轮踩过的坑就是深档掉到另一个色相上（`#a94e0b` 看着偏褐），
  于是「亮橙条」和「深褐按钮」被读成两种橙。

  **橙越亮，当白底小字越差，这是算术不是调参。** 所以亮橙仍然只当面。
- `--c-watch-bg` / `-2` / `-3` 的 RGB 跟着换成 `rgba(250, 146, 5, …)`，
  alpha 三档 **0.12 / 0.20 / 0.03 一个不动** —— 红/橙/绿三级渐变浓度必须逐档一致，
  这条有断言钉着（`render.test.js` ②b）。

### 二、页面 5 敏感性表：**灰底整个撤掉，改墨黑描边**

**同一处反馈来两次**（第六轮「为什么有两块数据是灰的，也没有解释标灰的原因」；
第七轮「假设敏感性表格**仍有不明灰底数据**」）。第六轮的修法是「把两块减成一块 +
说明上移到表上方」，方向没错但**只解决了一半** —— 屏幕上确实只剩一格，
读起来还是「不明」。真因不在**数量**，在**语义**：

> 灰蓝底纹在这个界面里一律表示「淡的 / 次要的 / 不可用」（`.dim` 那一族、
> 空状态槽），而基准格恰恰是**读这张表的原点**、是全表最重要的一格。
> **用「次要」的颜色去标「最重要」的格子，读者只能读出「它为什么不一样」。**

**定案**：`background` 撤掉，改成 `outline: 2px solid var(--c-ink)` +
`outline-offset: -2px` + `font-weight: 700`。两个直接效果：

1. **底色消失 ⇒「不明灰底」这个说法本身不再成立**（不是解释清楚了，是没有了）；
2. 剩下的一个框，和上方说明里「**框住的那一格**」逐字对得上 —— 图例与画面同构。

**为什么是墨黑而不是橙**：橙的语义是「需关注 / 可行动」，基准假设是**读表的原点**
不是警报（页 5 逐类裁决早定过）；三色分工里「内容焦点」本来就归墨黑，
而这一格正是「要读的那个数」。**这一轮不翻案，只换实现。**

**为什么用 `outline` 不用 `box-shadow` / `border`**：`td` 在 `border-collapse`
下 `box-shadow` 会被相邻边框裁切；加 `border` 会把整表的列宽推歪一格。

## 2026-10-13 定案（第八 / 第九轮）：页 5 两处粘连 · 基准标记重做 · 橙面上的字

一条反馈里三件事，两件在页 5，一件是全局色。三件的共同点是：
**表面症状都不是真因，真因要靠量出来。**

### 一、页 5「绝对估值」面板粘连 —— 缝 = 0px，`两边都不认账`

**不靠肉眼判**：真机把 `.卡` 里每对相邻子元素的间距逐条量出来，
`.kv-grid`（六格假设表）的 bottom = **1302**，紧接的 `.v-target`（估值对象条）
top 也是 **1302** —— **缝正好 0px**。

真因是本仓库那一类老毛病：**两边都不认账**。
`.kv-grid` 只声明了 `gap`（管格与格之间），`.v-target` 只有 `margin-bottom`
（管它和下一个之间），**两者都没管这条缝**，于是塌成 0。
而 `.kv-cell` 和 `.v-target` 的填色 / 描边 / 圆角**是同一套**，
缝一为 0，两块就被读成一整块。

**落地**（`css/components.css`，写法照抄已有的 `.ro-stats + .v-target` 先例）：

```css
.kv-grid + .v-target,
.v-target + .v-target { margin-top: var(--sp-4); }
```

★ **16px，不是随手取的**：段与段之间的缝必须**大于段内的缝** ——
格与格之间是 `--sp-3`(12px)，所以段间取 `--sp-4`(16px)。
下面的 `.note` 仍留 12px：注记本来就该贴着自己那块。

★ 又一次「**接线**」而不是「改组件」：不去动 `.kv-grid` 或 `.v-target` 自身，
只补这条缝。改共享组件的属性会连带改到别页。

### 二、页 5「假设的敏感性」基准标记 —— 第三稿才找对**

| 轮 | 标法 | 反馈 |
|---|---|---|
| 第六 | 行轴 + 交叉格，**灰蓝底纹** | 「为什么有两块数据是灰的，也没有解释标灰的原因」 |
| 第七 | 只留交叉格，**墨黑描边 + 加粗** | 「假设敏感性表格被**莫名框起来且加粗**」 |
| 第八 | 撤掉描边 / 加粗 / 底纹，**在两轴表头上各挂一个「基准」小标签** | 待反馈 |

前两轮都当成**配色**问题处理（「灰蓝 = 次要，用错了语义」→ 换成「墨黑 = 焦点」），
但两次反馈落在同一个词上：**「没有解释」「莫名」。**

> 真因从来不是颜色，是**那个标记身上没有任何字**。
> 底纹也好、框也好，都是纯视觉符号，必须靠旁边的说明去**解锁**：
> 读者先读说明，再回头到表里找那一格，找不到或懒得找，剩下的读数就是「莫名」。
> **换多少次颜色都治不了这一层。**

**定案**：把字挂上去，而且挂在**有名字的地方** —— 表头本来就在说
「这一行是 WACC 4.63%」「这一列是永续增长 3.00%」，在它们后面接一个「基准」，
读者不必对照、也不必找，读到表头就结束了。交叉那一格被两把尺子同时指到，
**格子里不需要再有任何记号**。

★ 为什么标在轴头上而不是格子里（**试过、量过、否决**）：
在基准格里放标签，标签就进了这一列的 intrinsic width —— 实测列宽从
**162px 被撑到 225px**，其余五列被挤成 139/139/153/154。**等宽是这张矩阵的
读法本身**（横着比「WACC 每动 0.5% 价怎么变」），列一参差就没得比。
改绝对定位可以不吃宽度，但 1600px 下只剩 34px 富余，视口一到 1250 就压到数字上。
轴头这一侧相反：第一列本来就由「WACC ＼ 永续增长」这个长表头撑着，
1200px 下还有 165px。**代价是零。**

★ 标签用灰蓝不用橙：橙的语义是「需关注 / 可行动」，基准假设是**读表的原点**，
不是警报（与第七轮同一条理由）。实现是 `.cell-tag`（见 `css/components.css`）。

★ 顺带把 `miniTable()` 改成表头/表体都能吃 `{text, cls, tag}`；
**不带 tag 的格子仍走纯 `textContent`** —— 顺手给所有格子包一层 `<span>`
会改动另外三张表的输出，而那三张有测试钉着，没必要为一条新特性去动。

### 一、橙面（按钮 / 两个胶囊）上的字：深档 → **白**

完整推导、三案实机对照、以及「为什么达 AA 只有压深橙面一条路」见 **§2c**。

### 二、守卫从「钉对比度」改成「钉取舍」

第九轮那条 `色相差 < 8° && ≥ 4.5:1 && hover 后 ≥ 4.5:1` 拆掉对比度那半条，
换成两条：① 三处橙面必须都走 `--c-on-primary`（拦半截改法）；
② `--c-watch` 必须仍是 `#fa9205`（拦「为凑对比去压深橙面」）。
**理由：一个永远红的守卫比没有守卫更糟。** 详见 §2c。

### 三、顺带发现：第九轮那条守卫**当时是红的**

写这一轮的守卫时才发现，第九轮那条断言读的是**注释里的退役色号** ——
`base.css` 注释里那句「接替原来的 `--c-watch: #c9922f`（黄）」被正则
当成了 `--c-watch` 的第一条匹配，`find()` 取了它。
于是它算的是 `#c9922f` 而不是活的 `#fa9205`：

- 对比 **4.41:1**（< 它自己的 4.5 门槛），hover 后 **3.92:1** —— **两项都不达标**。
- 也就是说：**按它自己的数字，它当时就应该红。**

修法：抽令牌前先剥注释（`stripComments`）。这条已记进 `docs/EDGE_CASES.md` #133。
