# FinScope 前端（E 的角色）

产品、网页、前端渲染与设计。**只读 D 定义的统一数据接口，不重新计算任何数据。**

---

## 怎么跑起来

双击 `index.html` 即可。不需要装任何东西，不需要起服务器，不需要联网。

> 最终交付物是按「双击就能打开」设计的，所以不引 CDN、不 fetch 本地 json、
> 不用 ES Module —— 这三样在 `file://` 协议下都会被浏览器拦掉。

## 目录说明

| 路径 | 作用 |
|---|---|
| `index.html` | 主页面，六段单页。**换数据源只改这个文件里的两行** |
| `app.js` | 入口调度：加载数据、生成导航、路由、`FinScope.ui` 工具 |
| `css/` | `base` 设计令牌与归零 → `layout` 版面 → `components` 零件 |
| `js/` | `format` 统一口径 → `contract` 消费端契约 → `dataLoader` 唯一数据入口 |
| `js/pages/` | 六个页面各一个文件，互不干扰 |
| `data/` | `real_data.js` 统一数据对象、`real_memo.js` 投研简报绑定表（**页面 6 的数据源**）；`mock_data.js` **只给 `tests/` 用，页面不再读它** |
| `a/` | **A 的产物**：`tokenize.js` / `search.js`（检索内核）、`data/shard_*.js`（9 家年报正文 17 MB）、`data/metrics.js`（抽取结果 95 KB）。页面 1 的看板与问答读这里 |
| `tests/` | 自测脚本。改完代码跑一下，比肉眼看靠谱 |
| `tools/` | 只读/构建脚本：`layout-audit.js`（版式审计，读源码文本）、`layout-probe.js` + `probe-harness.html`（**真机版式体检**，headless Chrome）、`interface-check.js`（接口体检）、`build-data.js`（把 D 的 JSON 包成 `.js`）、`build-final.js`（打包成 `05_Output/Final.html`） |
| `styles.css` | **打包用**的样式聚合入口（三个 `@import`）。开发期不走它 —— `file://` 下 `@import` 在部分浏览器会加载失败，所以 `index.html` 用三个 `<link>` 直接引 |
| `docs/` | 工作底稿：页面规格、接口约定、边界情况、演示脚本 |

> ★ **`vendor/` 已于 2026-10-13 撤除**（Chart.js 与本项目已无关系）。
> 当初留它的理由是「离线演示不能走 CDN」，那条理由仍然成立 ——
> 但现在**一份第三方库都不需要**了：全站零 canvas、零图标字体、零图片、零在线字体，
> 只有自己写的 CSS 和原生 JS。所以「断网也能跑」从「靠本地化了库」升级成
> 「压根没有外部依赖」。详见下面的已撤清单。

### 数据是从哪来的

页面**不读 `mock_data.js`**。演示期读 D 的两份产物：

```
D/output/…/unified/600519.SH_2025.json   ──build-data.js──▶  data/real_data.js
D/output/…/reports/600519.SH_2025/memo.json ─────────────▶  data/real_memo.js
```

两步都必须走 `build-data.js` 包一层 `window.FINSCOPE_DATA = {…}` /
`window.FINSCOPE_MEMO = {…}` —— `file://` 下 `fetch()` 本地 `.json`
会被 CORS 拦掉，所以交付物里不能有裸 `.json`。

## 怎么自测

```bash
node tests/run.js
```

两个测试文件：

| 文件 | 查什么 | 什么时候跑 |
|---|---|---|
| `tests/data.test.js` | 格式化口径、取数、指标中文名、溯源反查 | 改 `dataLoader` / `format` / 数据源后 |
| `tests/render.test.js` | 用 DOM 桩把**六个页面的 render() 真跑一遍**，并断言页面结构 | **每次换数据源后必跑** |

`render.test.js` 的价值在于：`node --check` 只能证明语法没写错，
跑 `render` 才能证明跑得起来。**接入 D 的真数据后先跑它** ——
缺字段的页面会在这里暴露，而不是在演示现场。

它还会报告 `sources[]` 覆盖率：`risks[].evidence[]` 里有多少条在
`sources[]` 中找不到对应条目（找不到就标不出年报章节）。这个数字可以
直接用来量 A 的抽取覆盖率。

### 交付前必跑的四条

```bash
node tools/build-data.js                                    # 1 从 D 的 JSON 重建 data/real_*.js
node tools/interface-check.js data/real_data.js             # 2 接口体检（按人汇总缺口）
node tests/run.js                                           # 3 全部测试
node tools/layout-audit.js                                  # 4 版式审计（读源码文本）
```

### 再加一条：真机版式体检

```bash
node tools/layout-probe.js --page all                       # 六页 × 11 档宽度
node tools/layout-probe.js --final --page all               # 量打包后的 Final.html
node tools/layout-probe.js --page p1 --chip 3 --qa          # 带公司数据与问答一起量
```

**为什么光跑 `layout-audit.js` 不够**：它读的是**源码文本**，能说
「这个令牌被引用了 24 次」，但说不了「这两块在 1150px 下压在一起了」。
版式缺陷只有真浏览器 + 真宽度才量得到 —— 用户报的「两个面板重合」
就是这么一条，静态审计永远看不出来。

这个工具之前不存在，代价是同一件事被一次性脚本重做了七八遍，
而且**同两条死路走了两遍**。它把三个容易重新踩的坑固化在里面
（`.vr-grid` 背景层的 19 条假重叠、「格高 > 1.6 倍行高」和
`td.scrollWidth > td.clientWidth` 两条假溢出判据）——
细节写在 `tools/layout-probe.js` 的文件头。

**`interface-check.js` 的输出可以直接发给队友** —— 它把缺口按 A / B / C / D
分组，每项标出路径与中文名。页面 6 的数据源是另一份产物，脚本会自己找
同目录的 `real_memo.js`（也认 D 的 `reports/<key>/memo.json` 目录约定）；
两份都找不到才报「投研报告：整块未提供」。

## 核心约定

### 1. 只有一处碰原始数据

所有页面取值一律走 `FinScope.data.get("financials.revenue")`，
不许写 `data.financials.revenue.value` 这种长链。字段名变了只改 `dataLoader.js`。

### 2. 只有一处拼字符串

所有数值展示一律走 `FinScope.fmt.*`，不许自己 `value + "亿元"`。
同一个数在全站长得一模一样。

### 3. 三条数据口径

| 约定 | 说明 |
|---|---|
| 金额单位 | 一律「亿元」 |
| 百分数 | 一律用小数传递，`0.184` 代表 `18.4%`，前端负责 ×100 |
| 缺失值 | 一律传 `null`。**不要传 `""`、`0`、`"N/A"`** —— `0` 是有效值 |

### 4. 颜色语义

**三色分工**（2026-10-12 改版定案；完整理由见
`docs/E_PAGE_SPEC.md`「共享段 · 配色 / 玻璃 / 面板 / 字体定案」）：

| 色 | 令牌 | 管什么 |
|---|---|---|
| 灰蓝 | `--c-primary*` | **结构 / 可点 / 参考** —— 导航、链接、浮层、估值标尺。凡是组织版面而不是喊的，都归这里 |
| 墨黑 | `--c-ink` | **内容焦点** —— 品牌字、要读的那个大数；同时是深色侧边栏的底 |
| 橙 | `--c-watch*` | **强调 = 可行动 + 需关注** —— 主按钮、预警/关注标记、风险卡底色 |

⚠️ **橙的预算：每屏最多 1–2 处。** 橙是全站唯一暖色，铺开就等于没有强调。
改版前 `--c-primary` 一个蓝在页面 4 被引 13 次、页面 5 引 10 次，
什么都用它等于什么都没强调 —— 三色分工就是为了解决这个。

**橙只有一个色相，靠「面 / 字」分工**（2026-10-13 第六轮定案，第十轮改定字档）：

| 令牌 | 值 | 只用在 | 对比度 |
|---|---|---|---|
| `--c-watch` | `#fa9205` | **面** —— 按钮底 / chip 底 / 色条 / 边框 | —— |
| `--c-watch-ink` | `#aa6300` | **字**，压在**浅底**上（全站仅 `.warn-title`、`.is-watch` 两处） | 白底 = **4.67:1** |
| `--c-on-primary` | `#ffffff` | **字**，压在**橙面**上（主按钮 / 关注胶囊 / 待核验胶囊） | 橙底 = **2.29:1** ⚠️ 低于 AA，见下 |

★★ **橙面上的字是白**（2026-10-13 第十轮改定）。
原话：「**橙色按钮/标注的内部字体换成白色**」。
白不新开令牌 —— `--c-on-primary` 的既有角色就是「压在实底上的白字」，
所以第九轮那个专用令牌 `--c-watch-on` 已经删掉，家族回到 5 个。

⚠️ **这一档的对比是 2.29:1，低于 WCAG AA 的 4.5:1。这是知情的取舍，不是漏算。**
想「修好」它只有一条路：把橙面压深到相对亮度 ≤ 0.183，也就是 `#b35f00`
这一带的**褐色**（+白 = 4.61:1，确实达标）——
但那样「按钮橙」和「色条橙」就裂成两种，而那正是第六轮被否过的东西。
实机对照过三案（见 `docs/E_PAGE_SPEC.md` §2c），结论是维持 `#fa9205`。

★ **改色号时**：`--c-watch-ink` 与 `--c-watch` 的色相要贴在一起
（34.5° / 34.9°，**< 8°**）—— 上一轮踩过的坑就是深档掉到另一个色相上，
于是「亮橙条」和「深褐按钮」被读成两种橙。
`render.test.js` 有断言钉着「三处橙面的字都走 `--c-on-primary`」+「橙面仍是 `#fa9205`」。

★ 为什么橙要两个色号（`--c-watch` 亮档 + `--c-watch-ink` 深档）：
**「够亮」和「能当白底小字」在算术上互相矛盾** ——
白底对比度 `#a94e0b` 5.56:1 → `#e2761e` 3.07:1 → `#f2831a` 2.61:1 →
`#fa9205` **2.29:1**，**越亮越差**。所以亮橙**只当面**；
需要橙字时用同色相里最鲜艳且仍达 AA 的深橙。**橙负责吸引眼睛，不负责承载阅读。**
理由与实测见 `docs/E_PAGE_SPEC.md` 第六轮 §一、`docs/EDGE_CASES.md` #123。

⚠️ 同一条算术在第十轮又咬了一口，方向相反：**橙面上的白字也够不着 AA**
（见上的 2.29:1）。这次没有再拆色号，而是**接受**它 —— 完整取舍见 §2c。

- **健康度 status**（判断谁好谁坏）：`good` 绿 / `watch` **橙** / `bad` 红。
  由 B 判断，前端只上色，不自己下结论。
  ★ `watch` 原来是**黄** `#c9922f`，2026-10-12 换成橙，2026-10-13 提亮到 `#f2831a`。
  换的不只是色号：黄在白底上当字用只有 2.9:1，连 WCAG 最低档 3:1 都不到。
- **涨跌 tone**（**当前全站零使用**）：A 股惯例红涨绿跌。
 页面 2 曾计划给三个大数配同比色，定案时否掉了 —— 那张卡已经在用 status 色，
  同一屏上红色会同时表示「上涨」和「差」，正是这条约定要防的事。
  三件套保留待用（真做多期趋势图时才会派上用场）。
  一旦启用，必须配 ↑↓ 箭头，且不得与 status 同屏。详见 `css/base.css` 顶部注释。

**硬约束：颜色只写在 `css/base.css` 的 `:root`，任何页面不得写死色值。**
`tools/layout-audit.js` 的 ⑥「色值零裸值」是这条约定唯一的自动闸门，目标 = 0。
另有两条不变式由测试钉住：**没有任何两个含义不同的令牌同值**、
**红/橙/绿三级渐变的浓度逐档一致**。

### 5. 界面表面与字体（2026-10-12 改版）

**两块面板。** 左侧墨黑面板（`.nav`）+ 右侧蓝灰内容面板（`.main`）。
四个外边缘和中间那道缝各留 16px，**背景渐变从缝里透出来** ——
「两块面板」的分割靠的是缝，不是描边（1px 的线在投影仪上会并成一片，
这条是被实际反馈打回来的）。面板圆角 `--radius-xl: 20px`，只给面板用。

**毛玻璃只在卡片这一层。** 面板本身**不是**玻璃 —— 玻璃套玻璃会让两层
0.6 白叠加，卡片和面板只剩 2–3 个色阶的差，等于都看不见。
所以面板故意做得**比卡片暗**：

```
背景渐变（只在缝里露出来） ＜ 内容面板（蓝灰） ＜ 卡片（白玻璃）
```

靠明度差分层，不靠线。一句话记法：**外壳玻璃，内容垫板。**

**字体。** `--font-sans` 首选 `Noto Sans SC`，回落 `Microsoft YaHei`；
**`--font-num` 与正文同族**（`var(--font-sans)`），数字不再单开一个字族。
**不引任何在线字体**（`file://` 双击打开是硬约束），所以只能吃系统字体。

> ★ **2026-10-13 实测更正（上一版的这段写错了，留在这里当教训）。**
> 上一版说「换 `Noto Sans SC` 之后 37 处 500/600 才第一次生效」——
> **从未发生**。演示机上 **`"Noto Sans SC"` 这个整族名没有被注册**
> （装的是 `Noto Sans SC Medium (TrueType).otf`，注册名带字重），
> 用假字体名基线量过：拉丁串在 `"Noto Sans SC"` 与 `"__NoSuchFontZZZ__"`
> 下**逐字节同宽** ⇒ 未解析。**全站中文一直是微软雅黑**，
> 那 37 处**到今天仍然空转**。
> 而 `Bahnschrift` 是**窄体且不响应字重**（`1,688.38` 只占汉字宽的 91.2%、
> 矮 5%、字重互异 1/7），拿它当数字字体，同一行里数字看着像另一个字号。
>
> **定案：数字不再单开字族**，层级改由**字号 + 字重 + 颜色**做。
> 完整证据、量法与修法见 `docs/E_PAGE_SPEC.md` 的
> 《2026-10-13 定案（第四轮）：字体实测》与 `docs/EDGE_CASES.md` #110–#117。
> ★ 教训一句话：**「沉默的回落」不会报错，只会看起来没那么好 ——
> 所以改完必须量一次屏幕到底渲染了什么，不能只看 CSS 里写了什么。**

**改样式必须先跑这两个：**

```bash
node tests/run.js          # 424 条（data 146 + render 278），含读 CSS / HTML 源文本的守卫
node tools/layout-audit.js # ①字号层级 ②颜色矩阵 ③圆角阴影 ④裸值 ⑤跨页复用 ⑥色值零裸值
node tools/layout-probe.js --page all   # 真机版式：六页 × 11 档宽度（见下）
```

> ⚠️ `tests/run.js` 只在最后打一句「✓ 全部通过」，**不打总数** ——
> 总数是各套件自己报的（`data 146/146`、`render 278/278`）。
> 单看 `tail` 很容易把**最后一个套件**的数当成总数（本文件里就写错过一次：
> 把 `render 278` 记成「全部 278」）。要总数就两个套件都看。

⚠️ `components.css` **不能出现 `@media`** —— 审计的 ① 用朴素正则切段落，
加了 `@media` 会让 ③④ 两项失准。要写媒体查询请放 `layout.css`。
⚠️ `.fin-bar` 的比例条**不能变橙**（`render.test.js` 钉着）——
它服务「读本表内各科目的大小」，是中性刻度，沾了 status 色就会被读成评价。
⚠️ `.ratio-row.st-not_evaluable` 那一道 2px 状态色**必须留在 CSS 里**，
且 `.st-ok` / `.st-good` / `.st-not_meaningful` **不能出现** ——
这条钉的是一个曾经真实存在的缺陷：CSS 写的选择器和页面挂的类名对不上，
色条一直是死的，只是没人对过 DOM 里的类名。

## 换数据源

```html
<!-- index.html：两行，而且**必须成对** -->
<script src="data/real_data.js"></script>   <!-- 统一数据对象（页面 1–5） -->
<script src="data/real_memo.js"></script>   <!-- 投研简报绑定表（页面 6） -->
```

**脚本顺序不能调换**（`index.html` 里已经排好）：
`data/real_data → data/real_memo → format → contract → dataLoader →
六个页面 → FINSCOPE_DEMO → app.js`。
六个页面模块要在 `dataLoader` 之后（它们注册时就取 `F.data`），
`FINSCOPE_DEMO` 要在 `app.js` 之前（`boot()` 读它）。
（这条链的最前面原来还有 `vendor/chart.umd.min.js` 与 `js/charts.js` 两环，
2026-10-13 一起撤了。）

若 D 交付的是 `.json` 文件，**不要直接 fetch**（`file://` 下会被 CORS 拦）。
用 `node tools/build-data.js` 包一层赋值，或者手工照做：

```js
window.FINSCOPE_DATA = { /* 原 json 内容 */ };
window.FINSCOPE_MEMO = { /* memo.json 原内容 */ };
```
