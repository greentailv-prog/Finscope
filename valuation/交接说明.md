# 估值模块 · 交接说明

给 **D（总集成）** 和 **E（前端）** 看的简版说明。完整文档见 `README.md`。

---

## 一、这是什么

分工说明里 **C 的交付**：Comps + DCF 估值模块，交付目录 `valuation/`。

比作业要求多做了一块：**SOTP（分部估值）** 与 **三法加权融合**——
三种方法各自算出隐含股价，再按权重合成一个结论，并配敏感性矩阵与三情景。

## 二、D 怎么接

### 调用的那个函数

对外只有一个入口，吃 dict、吐 dict：

```python
import sys
sys.path.insert(0, "valuation")
from engine import run

result = run(input_payload)      # input_payload 见 INPUT_SCHEMA.md
```

或者用命令行：

```bash
py valuation/cli.py run 你的输入.json
py valuation/cli.py value 600519 --peers peers.json     # 自动取数
```

### 往统一数据对象里填什么

D 定义的统一对象里，C 只负责 `valuation` 这一段：

```json
{
  "company":    { ... },
  "financials": { ... },        // A 填
  "ratios":     { ... },        // B 填
  "risks":      [ ... ],        // B 填
  "valuation":  { ... },        // ← 把 run() 的返回整体放进来
  "sources":    [ ... ]
}
```

**`run()` 的完整返回值可以直接整体赋给 `valuation` 字段**，不需要裁剪。
里面的 `dcf` 对应作业里的 `valuation.dcf`，`relative` 对应 `valuation.comps`。

### 需要 A 提供什么

DCF 和相对估值都要这些字段（**金额单位是元，不是万元**）：

| 类别 | 字段 |
|---|---|
| 利润表（逐年） | `revenue` `cogs` `ebit` `pretax_income` `tax_provision` `net_income` `interest_expense` |
| 现金流量表（逐年） | `da`（折旧摊销）`capex` `delta_nwc` |
| 资产负债表（最新） | `total_debt` `cash` `minority_interest` `preferred_stock` |
| 市场 | `price` `shares_outstanding` `market_cap` `beta` |
| 可比公司 | `peers[]`，每家有 `pe` `ps` `pb` `ev_ebitda` 等 |

逐年数组**长度必须等于 `years` 的长度**，缺失值写 `null`，**不要用 0 代替**。

### 数据源

C 自己带了一套取数（A 股走 akshare、美股走 yfinance），
所以**即使 A 的表还没好，C 也能独立跑通**。

接了 iFinD 官方接口后会自动优先使用（见 `README.md` 的「官方数据接口」）。

## 三、E 怎么用

E 不重新计算，只渲染。有两份产物：

| 产物 | 给谁 |
|---|---|
| `output/<标的>_valuation.json` | **E 渲染用**，结构见 `OUTPUT_SCHEMA.md` |
| `output/<标的>_valuation.xlsx` | 给人看的 Excel 底稿 |

### 前端最该展示的四个数

```
valuation.blended.blended_per_share    融合每股价值
valuation.blended.current_price        当前市价
valuation.blended.upside               上行空间（小数，-0.15 = 下跌 15%）
valuation.blended.verdict              显著低估/低估/大致合理/高估/显著高估
```

### 作业要求 E 画「Comps 估值区间 + DCF 估值区间」

| 要画的东西 | 取哪个字段 |
|---|---|
| Comps 区间 | `relative.range_low` ~ `relative.range_high`（元） |
| DCF 区间 | `sensitivity.grid` 的最小值 ~ 最大值 |
| 三情景 | `scenarios.bull / base / bear` 的 `per_share` |

### ⚠️ 必须展示的：`warnings`

`warnings` 是模型自动跑的交叉验证结果，**不是报错**，是**结论的一部分**。

典型内容：

> 算出的 WACC（4.64%）低于市场隐含折现率（8.31%）367bp。折现率偏低会让 DCF 结果系统性高于市价。

**这些必须显示在页面上**，不能折叠隐藏。原因见下一节。

## 四、一个必须知道的事（答辩会问）

用当前 A 股参数跑茅台，DCF 给 2,647 元/股，相对估值给 422 元/股，**差 5 倍**。

根因不是 bug：10 年期国债只有 1.8%（历史低位），CAPM 算出的折现率只有 4.64%，
但**市场定价隐含的折现率是 8.31%**。折现率低 → DCF 结果系统性偏高。

这是真实结论，**不要靠调参数把它抹平**，应该写进交付说明。
美股反向验证也成立：AAPL 算出的 WACC 比市场隐含值高 600bp，说明偏保守。

## 五、跑起来

```bash
cd valuation
py cli.py health                                   # 环境自检
py cli.py run demo/input_ashare_600519.json        # 离线演示，立刻能跑
py cli.py value 600519 --peers demo/peers_baijiu.json   # 真实取数
```

依赖：主程序只要 `openpyxl`；取数需要一个装了 `akshare`/`yfinance` 的解释器，
`cli.py health` 会告诉你用的是哪个。

## 六、边界

| 做不到 | 说明 |
|---|---|
| 分业务收入构成 | 免费源不提供，SOTP 需手工提供分部数据 |
| A 股折旧摊销 | 新浪源缺该科目，会用营业利润近似或按收入比例估算 |
| 可比公司倍数 | 未接 iFinD/Choice 时需人工确认 |
| 银行 / 保险 | 不用标准 DCF，应改用 DDM 或剩余收益模型 |
